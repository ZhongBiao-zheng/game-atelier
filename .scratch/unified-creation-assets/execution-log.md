# 统一创作资产执行日志

## 2026-08-29 实现决策

- 资产运行时从不可变版本列表收敛为单一可编辑 `content`；同一 `asset_id` 原位更新。
- “使用”复制当时内容；只保留冻结标题作为弱来源，不保存可回写的资产或版本引用。
- 详情只保留“使用 / 编辑”；删除只在编辑页出现，二次确认后物理删除。
- Studio 与 Canvas 复用同一面板和编辑器；父级按钮与 Canvas `Esc` 也必须经过脏编辑退出确认。

## 迁移与安全

- v1 → v2 只在 server 启动阶段执行一次。写入前把完整 `creation-assets/` 及每个会改写的
  Job/Canvas 文件复制到 UTC 时间戳目录；运行时永不读取备份。
- Job 在 per-job 锁内读取、按 `Job` schema 校验并通过正式写入口落盘；Canvas 同样持项目锁并按
  `CanvasDocument` 校验。旧字段统一转成冻结的 `creation_asset_source_title`。
- catalog 只保留 latest 内容，已归档项恢复；旧图片版本 blob 在备份完成后从活动目录清除。

## 审查反馈与修复

- 修复图片资产替换后旧 blob 遗留，并统一对删除路径做资产 blob 目录边界校验。
- 修复历史再次生成时丢失来源标题，以及 Studio 图片资产使用后没有来源标题的问题。
- 修复 Canvas 项目范围内新建提示词只检查局部列表、可能漏报全局重复的问题。
- 移除 Canvas 包导入后已无意义的资产关系 no-op；项目删除时的关系清理仍保留。
- 补齐 plugin 版本升级到 `5.33.0`。

## 已知边界

- 来源仅是单个不可点击标题快照；一次生成连续使用多个资产时，记录最后一次明确使用的资产标题。
- “保存并加入画布”只建立项目范围关系，不等同于“使用”，不会自动插入画布内容。
