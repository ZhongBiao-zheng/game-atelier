# ComfyUI 工作流共享：Windows 实机测试需求

给 Windows 上的 agent 执行。Mac 上只用假 ComfyUI 验过，这份测试只验 Mac 验不了的东西：真实 ComfyUI、真实工作流、显卡、Windows 路径与编码、两人排队、取消与中断。

## 0. 规则

1. **不碰正式数据**：主机和成员都用独立 data root（见第 1 节），不改 `~/game-atelier`，不改欧总机器上正在用的 Atelier 配置。
2. **不改代码**：发现问题只记录（现象、复现步骤、日志、截图），不修。
3. **不调计费模型**：本测试只用 ComfyUI，费用应全部为 0；出现非 0 费用即记为问题。
4. 每一步记录「做了什么 / 看到什么 / 是否符合预期」，写进第 6 节的报告。截图放 `C:\atelier-test\shots\`，文件名用测试编号（如 `T3-2.png`）。
5. 遇到阻断（服务起不来、ComfyUI 连不上），先记录完整报错与 `.runtime/server.log` 末尾 100 行，再继续能做的项。

## 1. 环境准备

| 项 | 要求 |
|---|---|
| 代码 | 仓库 `main`，提交须包含 `81ca1a71`（输入识别修复）。记录实际 commit：`git log -1 --oneline`；首轮已测基线为 `07405b23` |

| 工作流 | 飙哥提供的真实工作流，至少：局部重绘、分块高清放大、LoRA 文生图各一个。在 ComfyUI 里能正常手动跑通 |

## 2. 导出工作流（准备步骤）

1. 在 ComfyUI 里打开每个工作流，确认能手动跑通。
2. 把要暴露给成员的输入节点标题改成 `in:<显示名>`，例如 `in:提示词`、`in:原图`、`in:遮罩`、`in:LoRA 强度`、`in:输出宽度`。
3. 输出节点必须是 `SaveImage`（不是 PreviewImage）。
4. 用 **Export (API)** 导出 JSON（不是普通 Save）。记录三个文件名。

## 7. 首轮问题修复后的复验

首轮 [Windows 报告](https://github.com/ZhongBiao-zheng/game-atelier/blob/feat/comfyui-windows-acceptance-report/docs/acceptance/2026-11-02-comfyui-windows/REPORT.md)
为 16 项通过、2 项失败、13 项未测，不能作为完整验收通过。以下复验追加到原报告，保留首轮记录。

### P1 / P2：输入类型与主提示词

1. 拉取最新 `main` 并重启隔离测试 Atelier。保持 ComfyUI 在线，在隔离 data root 中**新建导入**原带标签工作流，使用不同名称；不要先手工改类型。
2. `LoraLoaderModelOnly.strength_model` 的 JSON 默认值仍为整数 `1`，导入后应自动显示「小数」，保留 ComfyUI 声明的范围和步长。创作台填写 `0.8`，应能提交，发送到 ComfyUI 的值仍为 `0.8`，不再出现类型错误。复验 T1-4、T2-1。
3. `CR Text` 的标题为 `in:提示词` 或 `in:prompt` 时，`text` 字段应自动显示「提示词」；创作台主提示词应写入该字段。普通文本、负向提示词不能被覆盖。截图导入框和提交参数。
4. 自动映射优先选择 `text`、`prompt` 字段；都不存在时，节点必须只有一个字符串字段。多个不明确字段仍由管理员手动选择；下拉选项不转成提示词，最多自动声明一个主提示词。
5. **既有工作流的声明不会被自动重写。**「重新导入」保留管理员保存的类型。继续使用旧工作流时，在编辑框把 LoRA 强度改成「小数」（切换类型后重新填写默认值），把 `CR Text.text` 改成「提示词」并保存；成员端随后刷新模型目录。
