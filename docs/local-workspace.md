## 目标与边界

用户打开网站，在明确连接本机服务后使用 Atelier；项目、画布、生成记录与媒体仍保存在自己的
`data_root`。外部 Codex / Claude 可以加载已有工作流 Skill，通过受限 MCP 工具准备任务；用户批准后，
由同一个本机服务执行生成，并在工坊中看到结果。

“数据在本地”指持久化归属，不代表数据永不出机：生成时选中的提示词和参考素材会发给模型供应商，
Agent 读取的上下文会进入所用 Agent 的会话。网站代码在获得连接授权后也能读取获授权的本机内容，
因此网站本身是需要信任的软件，不是一个无权限的静态外壳。

本次不做：云端项目数据库、账号同步、跨设备访问本机、云中转、本地网络扫描、任意 shell / 文件代理、
网站内嵌完整 Agent IDE、自动运行画布或后台无人批准的付费生成。保留现有本地页面启动方式，
不把数据改存 IndexedDB，不重做存储格式，不改供应商协议与价格。

## 两条入口，一个执行中心

```text
HTTPS 网站 ── 用户配对 ──┐
本地页面 ── 同源会话 ───┼─→ viewer-server (127.0.0.1)
                       │     ├─ 项目 / 画布 / 媒体 API → data_root
Codex / Claude         │     └─ 工坊服务 → 人工批准 → Job Runner → 供应商
  └─ Workflow Skill    │                                  └─ 本机产物 + Job
      └─ stdio MCP ────┘
```

不另起一套保存服务、生成队列或供应商调用层。MCP 适配器只翻译协议和返回结果，不直接写 Job、
读密钥或调用供应商；浏览器只提交意图，不能声明自己已获批准。连接契约见
[本机连接](contracts/local-connection.md)，工具与批准契约见[工坊 MCP](contracts/workshop-mcp.md)。

## 模块职责

以下是目标边界，不要求逐项创建一个类或目录。

- **本机连接模块（viewer-server）**：运行实例、网站配对、本地会话、Agent 授权、撤销、路由能力检查、
  媒体凭据。它不能修改项目内容或决定生成参数。
- **Web 连接层**：React 原生状态保存连接状态；统一 JSON、上传、下载、媒体、SSE 与取消。
  页面不读令牌、不拼接本机地址。业务 API 继续维护自己的输入输出类型。
- **工坊服务（Python 共享业务层）**：显式目标解析、上下文、文档修订、准备生成、冻结输入、
  幂等、批准与调度。Web / MCP / 工作流 CLI 在各自授权入口后调用它。
- **MCP 适配器**：官方 SDK 的 stdio 工具表；只调用工坊 HTTP 能力，不提供通用 HTTP 或文件工具。
- **Job Runner 与 callers**：保留实际生成、供应商任务 ID、计费记录、产物校验和落盘职责。
- **Workflow Skill**：负责对话、创作步骤、参数解释与人工反馈；不是权限证明或后台执行器。

## 产品交互

### 网站连接（后续阶段，当前未开放）

未连接时只显示“连接本机”和启动说明，不出现空项目列表，也不把连接失败表现成数据丢失。
本机启动入口可打开网站并带上无凭证的回环地址；用户在本地页面确认网站来源，复制一次性连接码，
到网站完成配对。浏览器自身的本地网络权限提示仍由用户批准，产品不绕过。

连接成功后进入现有界面。正常态只有一个低干扰的连接入口，展开后查看目标、断开或重连；
配置密钥、切换数据目录、管理授权都跳回本地管理页，不给网站发送原始密钥。
连接错误在连接面板内给出具体原因，不在画布或每个节点重复堆文案。

同一运行实例仍只允许一个交互式编辑页面；新页面显式接管前，旧页面有机会保存或导出草稿。
不能静默清空草稿或让两个编辑器同时持有写权限。本地授权管理页不是第二个编辑器。

### 工坊 Agent

用户在本地授权一个 Agent 会话访问选定项目，再从 Codex / Claude 使用 Skill。
Agent 先取得带目标 ID 的上下文，按工作流整理内容、准备生成；Atelier 展示目标、模型、
参考素材、数量、参数与预计费用，用户点击批准后执行。Agent 可查询状态和读取已授权结果。

第一版的付费批准放在 Atelier 页面，而不是相信模型传来的 `confirmed: true`。
这是拟定的安全交互，会随 PR 一并供用户评审；不以“已安装 Skill / 已连接 MCP / 对话里写了同意”
冒充服务端可核验的批准。无浏览器后台自动出图不属于本版。

## 验收与发布规则

1. 数据仍在同一个 `data_root`；关闭网站 / Agent 后文件和已批准任务不依赖浏览器存活；
   清理网站缓存不删除文件，但会断开连接。静态站点不包含真实项目、密钥、运行目录或诊断日志。
2. 恶意 Origin、DNS rebinding Host、无凭证 API / SSE / 媒体、过期或重复配对、跨项目 ID、
   伪造确认、并发批准、旧修订覆盖、符号链接逃逸全部拒绝且不产生付费副作用。
3. 断网、切换本机地址、撤销、服务器重启和跨版本连接都有确定状态；旧响应不能写入新连接。
   不静默降级到不鉴权、不依赖关闭浏览器安全设置。
4. 大视频使用 Range 与原生媒体流，不能为了鉴权把全部素材一次性拉成 Blob；图库分页及媒体缓存有上限。
5. 重启不会重复计费：持有供应商 task ID 时仅续查；请求是否送达不明时标记待核对，禁止自动重发。
   不承诺外部供应商无法保证的“严格 exactly-once”。
6. 每个代码 PR 跑 `make verify`；UI 改动做真实页面验证。付费调用用 fake provider / fixture，
   不用用户密钥做自动回归；真实付费联调需另获明确授权。
7. 桌面 Chrome / Edge 的真实 HTTPS→回环链路为首个验证目标；Safari / Firefox 不在通过前宣称支持。
   Windows / macOS / Linux 分别验证启动、文件权限、锁与重启，不能把 CI 单测当浏览器真机验收。
8. 不自动合并、不切换用户现用服务、不推送网站生产部署；用户审阅后才决定合并及发布顺序。
