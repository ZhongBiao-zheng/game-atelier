# 桌面安装包在线安装：首次启动下载运行包

2026-11-19 飙哥定：「改成在线安装，首次启动再下载运行包。」推翻 11-17 批准的「安装器带种子运行包」（ADR-0040 里的种子做法）。带种子的安装包从未随 tag 发布，没有已安装用户，不做迁移与兼容。

## 背景

- 带种子的安装包 setup.exe 284.7 MiB、dmg 240.5 MiB，其中运行包 129–143 MiB；飙哥在 Windows 上下载安装包很慢。
- 在线安装不减少总下载量（安装包减半，首启再下运行包），只在运行包来源比安装包下载渠道快、或慢在浏览器下载大文件不能续传时才更快。这一点已向飙哥说明，他仍选择在线安装。
- 日常提交不改版本号，未发版的 CI 构建与已发布版本同号；只按版本号对应会让未发版的安装包静默配上已发布的旧运行包。

## 决定

- 安装包只带外壳与 `stage/runtime.json`：配套运行包的版本、文件名、整个压缩包的 sha256、版本目录的 `BUILD_ID`、契约级别。Windows 安装程序只复制应用文件，不联网、不碰运行包。
- 首次启动下载与外壳同版本的运行包。来源与命名只写在 `src/viewer_server/release_sources.json`，外壳与应用内更新共用：CNB 先不经代理、再走系统代理，然后 GitHub。
- 信任锚是构建时记下的 sha256：来源的 `.sha256` 只作预检，不符或取不到就跳过该源；下载完与「从文件导入」都按内嵌值校验。
- 运行包身份用版本目录的 `BUILD_ID`：与外壳同版本但 `BUILD_ID` 不同时替换（`build`），未发版构建因此不会静默沿用已发布的旧运行包；应用内更新解出的版本目录本就带 `BUILD_ID`，不会被误判。其他版本只要满足契约级别就保留，升级交给应用内更新（去掉 ADR-0040 的 `older`）。
- 失败出路：重试、从文件导入（Release 页上的运行包压缩包，或 CI 产物 `desktop-runtime-<平台>`）。不另发带运行包的离线安装包，不加第三个分发渠道。
- 断点续传、同源重试、卡住判定、磁盘空间预检；取消保留断点；解压或下载中退出先中止再退出。

## 实测与估算

| 项 | 带种子 | 在线安装 |
| --- | --- | --- |
| Windows setup.exe | 284.7 MiB | 约 142 MiB（以 CI 实测为准） |
| macOS dmg | 240.5 MiB | 111.1 MiB（本机构建实测） |
| 首次启动下载 | 0 | Windows 142.9 MiB、macOS 128.2 MiB |
| 首启到可用（估算，下载 + 解压 + 服务启动） | — | 10 Mbps：macOS 约 2 分钟、Windows 约 2 分 16 秒；50 Mbps：约 32 秒 / 40 秒 |

真机用时从 `shell.log` 的下载开始、下载结束（字节、用时、速度、换源）与页面可交互三行读出。

## 代价

- 首次启动必须联网，或手动导入运行包。
- 总下载量不变，换来的是安装包减半、断点续传与自动换源。
- 外壳多了下载、续传、校验与加载页的五个状态，冒烟需要本机假下载服务（未发版构建没有真实来源）。
- 未发版构建试装要多下载一个产物（`desktop-runtime-<平台>`）并在首启失败页导入。
