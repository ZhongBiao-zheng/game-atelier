# ADR-0028：模型路由方式与任务冻结顺序

状态：已接受（2026-10-25）

## 背景

控制台 v2 要求同模型支持自定义顺序、价格最低和轮流。原有“自动”仅按自定义顺序选择，网关提交估价与执行会分别选择，可能导致估价和实际渠道不一致。

## 决策

`keys.json.route_mode` 只保存非默认方式；自定义顺序仍由 `model_order` 表达。停用不删除偏好；删除 KEY 后只清理不再存在的模型路由。价格最低使用每个成员自己的模型 ID、计费组及本次实际参数调用统一估价器，未知价格稳定排在已知价格之后。列表使用单张图片，视频使用 5 秒、720p、16:9 预览；它是比较参考，不是本次提交报价。

轮流计数只存在本进程，以数据目录、模态、路由 ID 为键，重启重置。使用同一线程锁完成读取游标、选择、冻结顺序与递增。成功完成一次自动解析即消费一次；随后参数或额度校验拒绝不撤销游标，避免并发回滚破坏已发生的选择。纯预览不消费；指定 KEY 不消费。切换路由方式重置游标。

自动任务记录 `route_id` 和从首选开始的 `route_order`，客户端不能提供或覆写这组运行字段。重试只沿快照查找当前有效且未试的成员，实时应用停用、删除、权限、冷却和欠费限制。不加入新成员、不重算价格、不再消费轮流。原有“确定未执行才切换”的错误边界不变。

网关提交只选择一次，估价、任务首选与执行共享快照；幂等命中直接返回旧任务。文本代理首次选择一次，首字节前允许的重试复用顺序，每次检查权限。其他网关不得成为候选。

Canvas 批量保留每个步骤跨所有条目的同一渠道语义：预检纯预览并持久化步骤快照；用户确认启动时每个自动步骤消费一次，重复启动不再消费。预检到确认之间游标可能推进，但启动仍使用用户确认的首选与顺序，避免悄悄改变确认内容。每个条目的失败切换仍沿该步骤快照进行。启动前验证路由仍存在，配置失效时要求重新确认，不留下活动指针。

## 影响

快照仅存 alias，不存凭据。供应商配置和余额状态仍是实时判断依据。轮流不承诺跨进程公平；当前单 viewer-server 进程符合部署边界。历史任务没有顺序快照时沿现有顺序处理，不为历史文件补写或迁移。
