# 插件贡献点与随应用发布的服务端模块

Atelier 的可选功能（游戏美术、3D 等）以「插件」交付：基础功能保持精简，需要时在设置里启用。本决定以 ADR-0012 为前提，补充它没有规定的部分；ADR-0012 的正文不变。

## 决策

- 一个插件是一个自包含目录 `plugins/<id>/`：清单 `manifest.json`、界面源码 `ui/`、可选的服务端模块 `server/`、测试、入库的构建产物 `package/`。运行时只读 `package/`。
- 贡献点分三层，由清单声明：
  - **宿主声明式贡献**：添加节点菜单项、图片工具栏「更多」里的动作。清单里是纯数据，由宿主渲染；点击前不运行任何插件代码。
  - **沙箱界面贡献**：节点内容面（`node`）与编辑面板（`panel`）。按 ADR-0012 在 sandbox iframe 里运行，经 capability broker 与宿主通信。
  - **服务端模块**：后端路由与 Agent 工具。只有随应用安装包发布的插件（`source: bundled`）可以声明，对应 ADR-0012 所说「随应用发布、经审核的内建模块」。路由固定在 `/api/plugins/<id>/` 下，逐条在清单里声明方法、路径与读写类别；未声明的路径拒绝访问。
- 插件不新增导航入口，没有独立页面。功能只出现在画布节点、图片工具栏动作和由它们打开的面板里；管理入口是设置里的「插件」页。
- 官方插件随主程序安装包发布。「启用」是应用级开关，状态存 `<data_root>/.config/plugins.json`。未启用的插件只被读取清单，不加载界面，不 import 服务端模块。
- 包完整性：构建时为包内每个文件记录 SHA-256，并对整份锁文件计算包摘要（`digest`）。宿主把界面放进沙箱前按清单核对文件摘要。随安装包发布的包以安装包自身的 SHA-256 为来源依据；发布者签名推迟到插件独立分发时再做。
- 界面包是单个 HTML 文件，由宿主以本机会话取回、核对摘要后，用 `srcdoc` 放进 `sandbox="allow-scripts"` 的 iframe。沙箱是 opaque origin，读不到宿主页面、cookie 与存储，请求不带会话，因此不为包资源开免鉴权路由。字体由宿主传字节给沙箱注册。
- 沙箱页面 = 宿主的固定前缀 + 包内容。前缀依次是内容安全策略与一段前缀脚本，永远排在最前面；宿主不在包内容里寻找插入位置，因为包是不可信输入。策略不含任何网络来源。
- 宿主页面的响应头带 `Content-Security-Policy: frame-src 'none'`。没有任何指令能阻止沙箱帧把自己导航走，只有父页面的 `frame-src` 能拦住那次加载。
- 握手证明：前缀脚本在页面里放一个本次实例的 nonce，插件在消息通道上的第一条消息必须带回它；宿主在此之前不服务任何方法。握手发出时页面若已不是宿主拼的那份，对方拿到通道也用不了。
- 新增 capability `server.call`：沙箱界面经宿主调用本插件声明过的服务端路由。只对声明了服务端模块的 bundled 插件有效。
- 服务端模块不直接调用厂商或 Job Runner 内部函数；插件要生成内容只能提出生成草稿，由用户确认后走 Canvas Run 与 Job Runner，这样成本统计、路由与网关配额自动覆盖。入库检查强制这一条。
- 清单校验失败、版本不兼容、插件停用或缺失，都只影响该插件：其他插件与主程序照常工作，含该插件节点的画布照常打开，节点显示宿主占位并保留数据。

## 本期不做（ADR-0012 原方案里的内容）

第三方插件的安装与加载、URL 安装与 SSRF 防护、压缩包解包限制、发布者签名、迁移沙箱、未验证包流程；capability 中的 `graph.read`、`graph.propose`、`generation.*`、`clipboard.write`、`export.download`；依赖大文件的下载器；外部 MCP 的插件工具；团队主机指定成员可用的插件。清单声明了宿主尚未实现的 capability 或必需的大文件时，插件显示为「需要更高版本的 Atelier」，不可启用。

## 沙箱的网络隔离边界（2026-11-14 在 Chrome 157 实测）

被阻断的：`fetch`（含 `no-cors`）、XHR、WebSocket、EventSource、`sendBeacon`、图片 / 脚本 / 样式 / 字体的外部加载、动态 `import`、表单提交、嵌套子框架、弹窗、顶层跳转、把自己导航到别的地址（包括解析期间的导航与返回 204 的连续导航）。

已知残余，内容安全策略管不到：

- **`<link rel="prerender">`**：浏览器会对目标地址发起一次 GET，地址里可以携带数据。静态写在包里、或用 `innerHTML` 插入的都会生效；宿主页面的 `frame-src`、沙箱内的 `default-src 'none'`、`prefetch-src`、`navigate-to` 都拦不住。
- **WebRTC**：`RTCPeerConnection` 可以向任意地址发 STUN 包。前缀脚本把相关构造器置为不可用，实测直接使用与经 `about:blank` 子框架取回构造器都失败，但这是纵深防御，不构成边界。

`<script type="speculationrules">`（prerender 与 prefetch 两种规则，静态与脚本插入）在沙箱帧里没有发出请求；不带任何策略的对照组同样不发，所以这不是策略拦下的，而是浏览器不为这类帧执行推测规则。另外本策略的 `script-src` 不含 `'inline-speculation-rules'`。浏览器行为变化后需要重测。

因此不能说「沙箱内没有任何网络」。准确的说法是：内容安全策略能管的通道全部关闭，另有上述两条残余；插件读得到的只有它自己的节点数据和用户连给它的素材，这些数据在残余通道上可以被带出。对第三方插件的信任还要靠审核与发布者签名。将来的桌面外壳应在壳层禁用 WebRTC 与预加载。

## 开放第三方插件之前必须完成

本期只加载随安装包发布的官方插件。下面每一项完成之前，不加载来自其他发布者的包：

1. 包签名与发布者校验（ADR-0012 的安装器、摘要与发布者绑定）。
2. 两条残余的处置：在桌面外壳层关闭预加载与 WebRTC；或把界面包改为只含脚本与样式、外壳由宿主生成，并用 Trusted Types 与前缀脚本关掉已知写法（仍是脚本层防御）。
3. 宿主页面完整的基线内容安全策略（目前只有 `frame-src 'none'`）。
4. 服务端对节点数据的深度与键数约束，用不在读盘时执行的校验方式实现（目前服务端只约束大小，浏览器侧约束全部三项）。
5. 本机会话 cookie 不区分端口：同机同时运行两个实例时会互相覆盖会话。
6. 插件界面协议里尚未实现的能力（`graph.*`、`generation.*`）与数据迁移。

## 后果

- 官方插件与将来的第三方插件在界面侧走同一条路径，`docs/plugins/` 描述的就是这条路径。代价是每个存活的插件界面是独立文档，各带一份界面运行库；节点内容面需要限制同屏数量并在视口外卸载。
- 插件界面源码在 `web/` 之外，类型检查、lint、设计守卫、构建都为 `plugins/` 单独接线（`web/tsconfig.plugins.json`、`plugins/eslint.config.js`、`web/scripts/build-plugins.mjs`）。
- `plugins/*/package/` 与 `web/dist/` 一样入库，受「干净构建后无差异」守卫约束。
