# 安装包版本目录与固定启动入口

为应用内更新准备自包含的版本目录，避免改写正在运行的 Python、依赖和应用文件。源码模式继续由一键启动器更新 Git 工作区。

## 决策

- 归档文件名仍包含版本和平台，归档内根目录固定为 `GameAtelier/`。
- 每个版本位于 `versions/<三段正式版本>/`，包含 `python/`、`app/` 和 `VERSION`；运行时与用户数据目录分离。
- 根目录 `current` 指定要启动的版本，`last-good` 记录最后确认可用的版本。初始包的两个指针均指向自带版本。指针更新使用原子替换。
- 固定启动器借助 `last-good` 的解释器运行选版本入口。`current` 不完整时恢复为 `last-good`，不扫描并选择最高版本。版本的解释器、入口及匹配的 `VERSION` 必须存在，路径不得逃出版本目录。
- Windows 计划任务指向安装根下的 `launch.ps1`，由该入口选择版本，并以前台子进程运行服务。任务参数不保存具体版本的 Python 路径；源码安装保留其运行环境路径。
- 旧布局需手动下载并在新目录解压一次；已安装的常驻任务需卸载重装并重新保存系统凭据。移动安装根目录同样需要重装任务。

## 分批交付

5.129.0 第一批交付布局、选版本入口及常驻路径，尚无更新器。该版与更早版本都需手动下载一次含更新器的安装包。

第二批实现独立下载和验证、维护状态、报到确认、代码及运行环境回滚。`pending.json` 与更新事务锁共同记录进行中的切换；重复启动不得打断仍活跃的等待事务。源码版只提示新版，由启动器更新。

- 准入在同一进程锁内检查维护状态并登记请求。已准入请求保持计数直至响应和后台任务完成；维护下先快照请求计数、再读持久任务，仅允许保守多计。Agent 待批准会话也计入存量，批准和取消仍可执行。
- CNB latest 跳转用于发现正式版本，附件及同源 SHA-256 下载失败时回退 GitHub。准备阶段使用独立临时数据目录导入新版，禁止继承上一轮事务 ID。下载/校验错误可重试，启动失败按版本封禁，手动检查可重试。
- 旧解释器运行脱离父服务的执行器，全程持更新锁；启停锁仅包住单次启停，等待时释放。Windows 由固定计划任务入口读取事务并启动，执行器不代建服务进程。
- 报到分两阶段：首先确认只读监听与实例身份，再允许应用初始化；初始化成功后再次确认实例，才原子写 current/last-good。报到前不运行既有数据整理/恢复；初始化失败时 last-good 保持旧版，自动回滚。数据格式变化仍必须可被旧版读取，代码回滚不回滚用户数据。
- 页面持久保存事务 ID 和重启开始时间；实例变化后刷新并重新鉴权，结果未落盘继续等待。等待任务最多10分钟，重启与回滚预算普通5分钟、常驻7分钟。
- 自动清理只在下次启动且无事务时进行，保留当前、上一个确认版本、已准备新版及执行中的解释器。

每次发布需用户单独授权，开发提交不 bump、不推 tag。
