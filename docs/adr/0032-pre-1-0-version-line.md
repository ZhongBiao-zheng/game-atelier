# 测试阶段使用 0.5.x，永久退役 5.x 号段

2026-10-31 用户确认：Atelier 仍处于测试阶段，版本号从 5.x 回到 0.5.x。
先发布 5.133.0 过渡版，待同事全部完成升级后，再经用户确认切到 0.5.134。

## 决策

- 主版本号 5 永久作为旧号段，比任何主版本号不为 5 的版本都旧，之后不再使用主版本号 5。
- 版本排序键为 `(旧号段标记, major, minor, patch)`；5.x 的标记为 0，其他为 1。同号段内部仍按数字比较。
- 0.5.x 每次发版增加末位：0.5.134、0.5.135……直到 1.0.0 正式版；1.0.0 沿用普通数字顺序。
- 保留所有旧 `v5.*` tag，不删除、不改写。旧发布的追溯、已分发客户端的更新路径以及发布产物关联仍需要这些 tag；排序规则使它们不会被新客户端当成最新版。
- CNB 正式 tag 的最大值选择、应用内更新提示、一键启动在切换分支前后的比较，以及更新日志的降序检查均遵循这条规则。
- 沿用 ADR-0029：开发提交推 main；发布 tag 每次另行取得用户授权，不把版本号提交视为发布授权。

## 过渡步骤

1. **B1：5.133.0。** 安装新的比较逻辑并保持 5.x 编号；旧客户端仍能用数字比较发现并安装它。此版包含本批 UI 改动，并告知下一版起改用 0.5.x。
2. 等用户明确确认同事全部升到 5.133.0。安装包的 GitHub latest 只返回一个 Release，未启动过的旧客户端可能跳过过渡版，因此不能省略这一步。
3. **B2：0.5.134。** 获得前一步确认后才改 manifest 和新增日志条目；历史 5.x 日志保持原样。推 main 后仍等待本次 tag 授权。
4. B2 发布后用 `gh release view --json tagName` 确认 GitHub latest 为 `v0.5.134`。

## 验证与待验证项

B1 的本地 Git 副本测试覆盖混合新旧 tag 的 CNB 发现、过渡版更新提示、新号段不降级、旧客户端发现过渡版、一键启动两个比较位置。测试先在旧实现上得到 5 项失败、1 项通过，再以新规则通过。启动器真实读取隔离 Git 仓库并输出“发现新版本 5.133.0 → 0.5.134”，没有触碰用户安装或远端发布。

Claude Code 插件市场是否允许从 5.133.0 更新到 0.5.134 **尚未实测**。B2 前需在安装了市场版插件的机器上验证，并将结果补入本节；若市场版会卡住，停止并报告，不自行增加兼容逻辑。当前 B1 不执行 B2，也不宣称市场版过渡已验证。
