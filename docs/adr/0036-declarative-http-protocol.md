# 自定义接口（声明式 HTTP 接口模板）

2026-11-14，为缩短接入新供应商的周期，按已确认方案实施。

## 背景

接入一个新供应商或新模型要写 Python caller、过约七处白名单并发版，只有开发者能做。
多数图片 / 视频接口是「POST 一个 JSON 或表单 → 直接回结果，或回任务号再轮询」，差异只在路径、
字段名和取值位置，可以用一段配置描述。

## 决策

- 新增领域对象「自定义接口」：一份版本 1 的 JSON 模板，描述提交请求、取结果与可选的轮询。
  一份一个文件，存 `<data_root>/.config/http-protocols/<id>.json`，内容是用户提交的正文原样，
  导出即这份文件。id 由服务端生成（`hp-` + 12 位十六进制）。
- 模型通过 `ModelSpec.protocol = "declarative"` + `declarative_id` 绑定模板。只允许
  `provider = custom` 的供应商绑定；已登记模型与内置 caller 不变，两者并存。
- 模板不含密钥与域名：地址只能写以 `/` 开头的相对路径，拼在供应商 `base_url` 之后，
  拼接后再核对一次源（scheme + host + port）未变；密钥只在 `keys.json`，按 `auth` 注入。
  提交与轮询都不跟随重定向。
- 校验只在 API 写入边界执行（`/api/http-protocols` 与 `/api/keys` 的绑定）。读盘重新解析，
  失败只让这一份模板不可用，不影响 `keys.json` 与其它模板；`KeySpec` / `ModelSpec` 不加校验器。
- 模型能力（比例、分辨率、时长、张数、参考图上限、首尾帧）只来自模板声明，前后端读同一份；
  后端按声明拒绝不合规参数，不做改写。
- 执行器 `callers/declarative.py` 接入 `dispatch` 与 `VIDEO_ADAPTERS["declarative"]`，
  `job_runner.run_job` 仍是唯一入口。重试政策与内置 caller 一致：只对未送达与 502/503/504
  重试；读超时与其余状态码当场致命。异步任务号先落盘再轮询，带任务号进入时只轮询；
  轮询复用 `video_poll.poll_responses`。
- 结果地址来自第三方响应，下载前检查：只允许 http(s) 与公网地址，按已校验 IP 建连，
  重定向逐跳重查；与 `base_url` 同源、走用户代理、TUN Fake-IP（仅 https）三种情况例外。
  响应、图片、视频各有大小上限。
- 自定义接口一律未计价，不参与内置渠道的「自动」路由组（路由 id 带模板 id），
  经局域网网关发布时只下发能力快照（不含模板与密钥），主机执行；设了金额上限的网关密钥不能用
  未计价路由（批次 4，2026-11-14）。
- 模板管理属于本机管理权限，网站会话、Canvas Agent 与网关成员不可调用。

## 参考图公网地址

`inputs.images.encode = "url"`：本机参考图经对象存储（`oss_upload.upload_for_url`）中转成
24 小时签名直链再发给厂商。是否已配置对象存储属于本机环境，不进结构校验，在保存与 validate
两个写入边界检查；之后对象存储被移除，执行时报错且不发提交请求。

## 不支持

动态签名、多步编排（先上传再提交）、回调 / 流式、二进制响应体、参考视频 / 音频、
局部编辑等内置专属能力、密钥放请求体、文本 / 音频模态、
一次点击循环多次提交。协议差异超出版本 1 表达能力的厂商仍按 ADR-0001 做一等 provider。

## 后续

`catalog` 字段保留给「目录发现」；`POST /api/http-protocols/validate`（错误列表 + 请求预览）
保留给「AI 帮我配置」共用。
