# 自定义接口（声明式 HTTP 接口模板）

2026-11-14，为缩短接入新供应商的周期，按已确认方案实施。

## 背景

接入一个新供应商或新模型要写 Python caller、过约七处白名单并发版，只有开发者能做。
多数图片 / 视频接口是「POST 一个 JSON 或表单 → 直接回结果，或回任务号再轮询」，差异只在路径、
字段名和取值位置，可以用一段配置描述。

## 决策

- 新增领域对象「自定义接口」：一份版本 1 的 JSON 模板，描述提交请求、取结果与可选的轮询。
  一份一个文件，存 `<data_root>/.config/http-protocols/<id>.json`，内容是用户提交的正文原样，
  导出即这份文件。id 由服务端生成（`hp-` + 12 位十六进制）。
- 模型通过 `ModelSpec.protocol = "declarative"` + `declarative_id` 绑定模板。只允许
  `provider = custom` 的供应商绑定；已登记模型与内置 caller 不变，两者并存。
- 模板不含密钥与域名：地址只能写以 `/` 开头的相对路径，拼在供应商 `base_url` 之后，
  拼接后再核对一次源（scheme + host + port）未变；密钥只在 `keys.json`，按 `auth` 注入。
  提交与轮询都不跟随重定向。
- 校验只在 API 写入边界执行（`/api/http-protocols` 与 `/api/keys` 的绑定）。读盘重新解析，
  失败只让这一份模板不可用，不影响 `keys.json` 与其它模板；`KeySpec` / `ModelSpec` 不加校验器。
- 模型能力（比例、分辨率、时长、张数、参考图上限、首尾帧）只来自模板声明，前后端读同一份；
  后端按声明拒绝不合规参数，不做改写。
- 执行器 `callers/declarative.py` 接入 `dispatch` 与 `VIDEO_ADAPTERS["declarative"]`，
  `job_runner.run_job` 仍是唯一入口。重试政策与内置 caller 一致：只对未送达与 502/503/504
  重试；读超时与其余状态码当场致命。异步任务号先落盘再轮询，带任务号进入时只轮询；
  轮询复用 `video_poll.poll_responses`。
- 结果地址来自第三方响应，下载前检查：只允许 http(s) 与公网地址，按已校验 IP 建连，
  重定向逐跳重查；与 `base_url` 同源、走用户代理、TUN Fake-IP（仅 https）三种情况例外。
  响应、图片、视频各有大小上限。
- 自定义接口一律未计价，不参与内置渠道的「自动」路由组（路由 id 带模板 id），
  经局域网网关发布时只下发能力快照（不含模板与密钥），主机执行；设了金额上限的网关密钥不能用
  未计价路由（批次 4，2026-11-14）。2026-11-18 改为：限额密钥也能用未计价路由，额度用光后一律拦下
  （团队可靠性第三批）。主机可给自定义接口等无同步价的模型手设每次调用价格（`per_call_cny`），设了即按它计价。
- 模板的读取、保存、删除与绑定属于本机管理权限，网站会话、Canvas Agent 与网关成员不可调用；
  接入说明与干跑校验（不写盘、不发请求、不读已有模板与密钥）对本机 Agent 连接开放（2026-11-20，第 5 批 5-6B）：
  Canvas MCP 的 `atelier_protocol_manual` 返回 `data/http_protocol_manual.md` 全文，`atelier_protocol_validate`
  走与设置页同一段校验与请求预览（占位服务地址，不接受 `base_url` / `model`；预览里与 MCP 适配器禁止字段同名的字段——鉴权头 `Authorization`、请求体或请求头里的 `api_key` 等——拿掉并在 `hidden_fields` 报路径）。
  有效的本机 Agent 会话即可调用，不另设能力开关、不挂项目；对 Agent 开放的只有这两项。
  干跑校验会透露一条本机状态：是否配置了对象存储（`encode: "url"` 时报需要先配置）。

## 参考图公网地址

`inputs.images.encode = "url"`：本机参考图经对象存储（`oss_upload.upload_for_url`）中转成
24 小时签名直链再发给厂商。是否已配置对象存储属于本机环境，不进结构校验，在保存与 validate
两个写入边界检查；之后对象存储被移除，执行时报错且不发提交请求。

## 不支持

动态签名、多步编排（先上传再提交）、回调 / 流式、图片与视频的二进制响应体、参考视频 / 音频、
局部编辑等内置专属能力、密钥放请求体、文本模态、
一次点击循环多次提交。协议差异超出版本 1 表达能力的厂商仍按 ADR-0001 做一等 provider。

## 2026-11-15 修订：音频模态

`kind` 增加 `audio`，模板版本仍为 1，只加字段，旧模板不变：

- 占位符 `$voice`、`$speed`、`$format`、`$lyrics`、`$instrumental` 只用于音频；用到 `$lyrics` 或
  `$instrumental` 即为音乐，否则为语音（族由占位符推出，不另设字段）。音频不能用比例、分辨率与参考图占位符。
- `options` 增加 `voices`（音色清单，第一个为默认）、`custom_voice`、`speeds`（离散档位，厂商刻度不同靠
  `derive` 映射）、`formats`（mp3 / wav / flac / opus / aac）、`max_chars`；语音一次一条，音乐最多两条。
- **二进制响应只对 `kind=audio` 且同步（不配 `poll`）的模板放开**：`result.body = "binary"` 表示整个响应体就是
  音频文件。图片、视频仍只收 JSON 响应。另加 `result.hex`（仅音频）。
- 二进制分支沿用提交请求的全部约束：请求目标恒为供应商 `base_url`；不跟随重定向；只对确定没送达与
  502/503/504 重试；响应头到达后读体失败当场报错、不重发；报错文本遮掉密钥。响应流式落盘，上限 50 MB；
  状态码 ≥400 或 Content-Type 为 JSON / 文本时只读前 64 KB 当错误文本。
- 格式按文件头判定（Content-Type 只作参考，冲突以文件头为准），只认 mp3 / wav / flac / opus / aac，
  与已有的音频后缀白名单一致；认不出直接失败，不落盘。URL、base64、hex 结果同样判定。
- 估价、网关发布、「AI 帮我配置」沿用上面的规则：音频模板未计价；网关只下发能力快照；起草接受 `audio`。
- 仍不支持：流式响应（SSE / WebSocket）、上传或复刻音色、裸 PCM、二进制响应配轮询。

## 后续

目录发现（2026-11-14 已实现）：模板可选 `catalog` 描述一次目录 GET（路径、列表位置、id / 名称 / 类别字段），
经现有 `models-preview` 入口（`protocol_id`）执行，出站规则与执行器相同；发现的模型不代表可用，分类可由用户修正，
目录里的价格不作为本机价格。

「AI 帮我配置」（2026-11-14 已实现）：编辑弹窗里粘贴文档或填公网网址，用本机已启用的对话模型起草模板，结果填进编辑区，
仍由 `validate` 预览、用户保存。文档只作资料（定界块 + 系统消息写死任务，请求不带 tools，服务端不按输出发请求）；
供应商密钥不进提示词，资料与输出里有明确密钥特征的值被遮掉；输出只保留模板顶层字段。每次点击调用一次、不重试，
记成一条 `namespace=assist` 的文本任务，在用量里归「接口配置」。

## 2026-11-19 修订：异步提交按统一「未确认」判据（团队可靠性第 5 批）

带 `poll` 的模板（异步提交）改用所有异步任务协议共用的判据（`callers/task_submission.py`）：

- 5xx 不再自动重发，按「提交结果未确认」处理：上游可能已建单后才超时，重发就是第二单。
- 连接建立前的失败照旧自动重试（确定没送达）；重试用尽仍连不上、响应头到达后读体失败、
  响应不是 JSON、按 `poll.task_id` 取不到任务号，都按未确认处理。
- 未确认用类型表达（`DeclarativeUnconfirmed`，继承 `DeclarativeError`）：经局域网网关时主机判
  `unconfirmed`、扣 0、不换到同路由的其他 KEY；报错文案不变。
- 同步模板维持上文的「只对未送达与 502/503/504 重试」：同步接口没有任务号，判未确认只会让用户手动重做，
  理由与内置同步 caller 相同。
