# 局域网网关：本机绑定规则的唯一例外

2026-10-16 用户确认：一台 Atelier 可以开启「局域网共享」，把自己持有的厂商 KEY 以网关形式提供给同一局域网的同事；
同事的 Atelier 新增「局域网 Atelier」供应商接入。主服务仍然只绑 `127.0.0.1`。

理由：KEY 分散在每台同事机器上，要人手工配置；全公司谁花了多少无处统计（定位指标「每张可用成片的成本」）。
网关让 KEY 集中在一台机器，并按人记录用量、按人限额。

约束（缺一条就不成立）：
- 网关是独立的 FastAPI app、独立端口（默认 5180），只挂 `/gateway/v1/*`；没有静态文件、没有 `/api/*`、不认 cookie。
- 默认关闭，只能在网关机器本机控制台的网关页开启。
- 除只返回 `ok/version` 的 `/gateway/v1/health` 外，每个请求必须带网关密钥（Bearer）；网关端按 sha256 鉴权，撤销立即生效（凭据存储方式见 2026-10-27 补充）。
- 网关接口不接受任何本机路径参数，参考图只能以文件上传；任务按密钥隔离。
- 上游厂商 KEY 不出网关：模型列表只返回 provider / base_url / model_id。

后果：
- 协议为 HTTP 明文，同一网络里可以抓到网关密钥和图片；一期按公司内网接受，HTTPS 列入后续。
- 接入端把网关当成路由组里的一个成员：网关连不上、密钥失效、额度用完时，按 5.91.0 的失败切换改用本机 KEY；
  同事本机 KEY 保留作为兜底。
- 网关任务不进网关主人的 `.runtime/jobs/`；任务文件与图片保留 24 小时后清理，使用记录按月保存在 `.runtime/gateway/usage/`。
- 一期只做图片生成（含参考图）；视频、画布局部修改 / 扩图、按金额限额后续再做。

## 2026-10-24 团队中转二期补充

协议 v2 按密钥提供金额窗口与模型/成员权限。文本及 Agent 透传独立挂在 `/gateway/v1/openai/*`，保留原 `/gateway/v1/models` 的成员快照；HTTP、Bearer、独立 app/端口、本机管理边界不变。文本请求转发 JSON（包含接入端编码的媒体内容），不读取网关本机路径；不转发接入端请求头，也不记录 prompt。流式响应保持字节原样，仅旁路提取用量；首字节发出后禁止失败重试。

- 生成协议覆盖图片、局部修改/扩图、图层拆分、视频、音频。参考素材按文件组上传，编辑过程图和图层元数据随产物回传。视频的上游订单只由网关持有，接入端重启后续查网关任务；提交未确认或已有订单时不重新提交。
- 限额改为日/周/月人民币金额窗口，按网关本地日历重置。受理时原子预占估价，终态释放预占并结算实际费用（无实际费用则成功按估价）；无价格调用计零并在用量中标出未计价。文本中转的估价按输入估算 token：内嵌图片每张按固定 token，其余请求字节 / 3（2026-11-19 定为 1600，避免 base64 把带图请求估成几万 token 误拦额度紧的成员；2026-11-20 付费实测一张长边 1024 的图约 3400–3800 输入 token，上调为 3800：预占偏高只会临近上限时提前拒绝，偏低会让成员在一次调用里超额；只影响预占，结算仍按上游用量）。成员按关联标记查回结算额：文本请求可带 `X-Atelier-Call-Tag`，主机只把它记在这把密钥自己的用量行上，`/gateway/v1/me?call_tag=` 只统计发起查询的密钥名下的行；成员端金额只取主机结算，不自己算（2026-11-20）。权限按模型路由和上游 alias 过滤，空数组表示无权限。
- 欠费按模态和 alias 持久化，一小时后允许试探，失败顺延；成功或本机管理页手动恢复后清除。全组欠费不强行重试。限流保留内存冷却，接入端遇到额度 429 按 Retry-After 冷却网关成员。
- 管理接口、用量和产物预览只在主服务，要求本机管理会话。实时事件复用主服务 SSE，只有 local 会话能收到生成任务 prompt，agent 会话不可接收；文本调用不提供 prompt。接入端本人额度由主服务代查并缓存 30 秒，失败静默隐藏。
- 两端要求协议 v2，不保留旧张数限额兼容路径。5.103.0 先交付 dev，Windows 真机联调完成后再由用户决定同步 main。

## 2026-10-26 成员角色与远程管理

用户确认管理员密钥（admin）与成员密钥（member）两级角色。网关 `/gateway/v1/admin/*` 接口只接受有效管理员，每次请求与写操作持锁时重新确认角色；SSE 定期及发送前复查，撤权结束连接。主服务仍仅绑定 localhost，浏览器经本机白名单代理访问远程管理接口，代理属于 LOCAL_MANAGEMENT。

- 管理员可发成员或管理员密钥、修改限额、撤销其他成员，读取团队用量、任务、操作日志；不能撤销或降级自己，最后一把有效管理员密钥只能本机撤权。
- 上游管理仅包含 alias 状态、恢复欠费和调整路由顺序；没有增删凭据、明文查询或文件路径接口。主服务设置和用户文件不对局域网开放。
- 管理操作写 `.runtime/gateway/audit.jsonl`，操作者、时间、动作、目标与脱敏前后摘要；创建密钥明文仅响应一次，不写审计。
- HTTP 明文仍可能暴露管理员凭据及团队用量，持有该凭据即可行使管理权限；只适用于可信内网。凭据撤销立即阻止新的管理请求。
- 这项决策取代二期“管理接口仅在本机”的限制；本机始终可撤销最后一位管理员。

## 2026-10-27 本机查看成员密钥

用户确认本机控制台需要随时查看和复制成员密钥。`.config/gateway.json` 保存明文和 sha256，沿用仅当前用户可读写的权限及原子写入；鉴权仍比较 sha256。已有仅哈希的未撤销记录在读取时持网关文件锁重发一次，更新哈希并写回，身份、角色、额度与创建时间保持不变。已撤销记录不重发，成员需换用新密钥。

明文读取只挂在主服务 `/api/gateway/keys/{id}/token`，要求本机管理会话并禁止响应缓存；远程网关和管理代理均不开放此路径。通用成员列表、修改响应及审计仍不含明文或哈希。远程创建密钥保留创建时返回一次明文的能力。这项决策替代此前只存哈希的约束，重发影响必须写入下一次正式发版日志。

## 2026-11-20 额度与范围的形状（第 7 批）

起因：Windows 真机测试里两处设置让成员用不了。只选了模型、关了「全部供应商」时，旧的两张名单（模型、供应商）取交集为空，成员连上网关拿到 0 个模型；额度可同时设日 / 周 / 月三条，飙哥要的是「一个金额 + 一个周期」。

- 范围：`scope` 取代 `allowed_models` / `allowed_aliases`。`None` = 全部模型；否则按供应商列出，`models: None` = 该供应商全部（含以后新增），列表 = 该供应商下的这些模型（供应商自己的 model id）。模型挂在供应商下，表达不出「选了模型但供应商没开」。判定只有 `gateway_access.member_in_scope` 一处。不再支持 `*` 前缀。
- 供应商别名建好后不能改，范围按别名记；删除供应商时从所有密钥范围里去掉它并记审计，同名重建不继承。
- 新保存不允许空范围（接口返回 422「至少选一个模型」）；旧数据转换出的空范围照常读出，界面显示「未选择模型」。
- 旧数据读入时转换并写回一次，转换表见 `gateway_keys.legacy_scope`：等价的照转；「选了模型、供应商全关」按「这些模型，经当时提供它们的各供应商」转（变宽，飙哥 2026-11-20 定「直接可用」）；「没选模型、供应商全关」仍为空范围；`*` 前缀展开成转换当时命中的具体模型（变严）。读不出供应商列表时这几把密钥本次按空范围读入、不写回。
- 额度：`quota = {cap_cny, period: day | week | month | none, since}` 取代 `limits`。周期按主机本机时区，每周从周一 00:00 起算，`none` 不重置、从 `since` 起累计。只改金额时 `since` 不变，改周期时重置为当时。旧数据一条原样转，多条取周期最长的一条并记日志。
- 回滚兼容（只严不宽）：更新失败回滚或手动装回第 7 批前的版本时，旧版不认识 `scope` / `quota`，会按 `allowed_models` / `limits` 判定。新版写 gateway.json 时，凡 `scope` 或 `quota` 不为空的密钥另写 `allowed_models: []`：旧版读到即一个模型都用不了；无限制的密钥照常可用。新版读入时条目里有 `scope` 键即视为已转换，忽略旧字段；旧版写回后丢了 `scope`，新版再读按旧字段转成空范围。写回转换结果失败（文件被占用、目录只读）只记日志，本次用内存里的配置，下次读时再写。删除条件：不再可能装回第 7 批前的版本时删，最迟与下面的 `limits` 兼容层一起在下次改 `PROTOCOL_VERSION` 时删。
- 读盘与写盘：gateway.json 读写同一个上限（2 MiB），写入超限时拒绝保存（413，文件不动）。范围条目的长度、条数与供应商唯一性只在接口写入边界查，持久化模型读盘时不查；旧字段旧版也读不出（类型不对、额度不合旧规则）时照旧报配置损坏，不放开。
- 兼容层（主机与成员版本不一致）：`/gateway/v1/me` 同时回 `quota` 与旧的 `limits` 列表（日 / 周 / 月一条，不重置为空），旧成员照常看额度；判定都在主机。移除条件：下次改 `PROTOCOL_VERSION` 时删 `limits`（届时旧成员本来就连不上）。`PROTOCOL_VERSION` 这次不动。
- 远程管理要求两边同版本：本机管理代理带 `X-Atelier-Admin-Api: 2`，主机的成员密钥管理接口（列表、新建、修改、重置、撤销、范围选项）对不带的请求回 426「远程管理需要本机与主机是同一版本的 Atelier」，旧版设置页把它当报错显示，不会拿到读不懂的数据。用量、任务、路由等形状没变的管理接口不查。新版管理端遇到旧主机时只提示更新主机，不发新字段。发版时更新日志要写明：远程管理成员要求本机与主机同一版本。

## 主机重启后续查 ComfyUI

ComfyUI 每一张对应一次 `POST /prompt`。主机每拿到一个 `prompt_id` 就将它与 SaveImage 输出前缀一起落盘。
重启后只在原供应商的原本机地址查询已登记的 ID。已完成的工作流从 history 下载全部输出，
仍在队列中的继续等待。队列里找不到时再查一次 history，覆盖两次查询之间刚刚完成的工作流。
两处都找不到时按未确认结算，费用为零。多张任务按已登记的工作流取回产物，数量不足时在任务警告中标记部分完成。

本机 Studio 与画布共用相同的订单查询和下载逻辑。启动恢复器凭本机任务里登记的订单重新调用 runner。
Studio 使用现有的 partial 状态，画布沿用候选的逐项结果，网关在成功响应的 warnings 中说明少取回的工作流数量。
