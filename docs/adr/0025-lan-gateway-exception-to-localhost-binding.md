# 局域网网关：本机绑定规则的唯一例外

2026-10-16 用户确认：一台 Atelier 可以开启「局域网共享」，把自己持有的厂商 KEY 以网关形式提供给同一局域网的同事；
同事的 Atelier 新增「局域网 Atelier」供应商接入。主服务仍然只绑 `127.0.0.1`。

理由：KEY 分散在每台同事机器上，要人手工配置；全公司谁花了多少无处统计（定位指标「每张可用成片的成本」）。
网关让 KEY 集中在一台机器，并按人记录用量、按人限额。

约束（缺一条就不成立）：
- 网关是独立的 FastAPI app、独立端口（默认 5180），只挂 `/gateway/v1/*`；没有静态文件、没有 `/api/*`、不认 cookie。
- 默认关闭，只能在网关机器本机的设置页开启。
- 每个请求必须带网关密钥（Bearer）；网关端只存 sha256，撤销立即生效。
- 网关接口不接受任何本机路径参数，参考图只能以文件上传；任务按密钥隔离。
- 上游厂商 KEY 不出网关：模型列表只返回 provider / base_url / model_id。

后果：
- 协议为 HTTP 明文，同一网络里可以抓到网关密钥和图片；一期按公司内网接受，HTTPS 列入后续。
- 接入端把网关当成路由组里的一个成员：网关连不上、密钥失效、额度用完时，按 5.91.0 的失败切换改用本机 KEY；
  同事本机 KEY 保留作为兜底。
- 网关任务不进网关主人的 `.runtime/jobs/`；任务文件与图片保留 24 小时后清理，使用记录按月保存在 `.runtime/gateway/usage/`。
- 一期只做图片生成（含参考图）；视频、画布局部修改 / 扩图、按金额限额后续再做。
