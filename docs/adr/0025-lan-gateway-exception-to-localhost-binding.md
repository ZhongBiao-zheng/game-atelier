# 局域网网关：本机绑定规则的唯一例外

2026-10-16 用户确认：一台 Atelier 可以开启「局域网共享」，把自己持有的厂商 KEY 以网关形式提供给同一局域网的同事；
同事的 Atelier 新增「局域网 Atelier」供应商接入。主服务仍然只绑 `127.0.0.1`。

理由：KEY 分散在每台同事机器上，要人手工配置；全公司谁花了多少无处统计（定位指标「每张可用成片的成本」）。
网关让 KEY 集中在一台机器，并按人记录用量、按人限额。

约束（缺一条就不成立）：
- 网关是独立的 FastAPI app、独立端口（默认 5180），只挂 `/gateway/v1/*`；没有静态文件、没有 `/api/*`、不认 cookie。
- 默认关闭，只能在网关机器本机的设置页开启。
- 每个请求必须带网关密钥（Bearer）；网关端只存 sha256，撤销立即生效。
- 网关接口不接受任何本机路径参数，参考图只能以文件上传；任务按密钥隔离。
- 上游厂商 KEY 不出网关：模型列表只返回 provider / base_url / model_id。

后果：
- 协议为 HTTP 明文，同一网络里可以抓到网关密钥和图片；一期按公司内网接受，HTTPS 列入后续。
- 接入端把网关当成路由组里的一个成员：网关连不上、密钥失效、额度用完时，按 5.91.0 的失败切换改用本机 KEY；
  同事本机 KEY 保留作为兜底。
- 网关任务不进网关主人的 `.runtime/jobs/`；任务文件与图片保留 24 小时后清理，使用记录按月保存在 `.runtime/gateway/usage/`。
- 一期只做图片生成（含参考图）；视频、画布局部修改 / 扩图、按金额限额后续再做。

## 2026-10-24 团队中转二期补充

协议 v2 按密钥提供金额窗口与模型/成员权限。文本及 Agent 透传独立挂在 `/gateway/v1/openai/*`，保留原 `/gateway/v1/models` 的成员快照；HTTP、Bearer、独立 app/端口、本机管理边界不变。文本请求转发 JSON（包含接入端编码的媒体内容），不读取网关本机路径；不转发接入端请求头，也不记录 prompt。流式响应保持字节原样，仅旁路提取用量；首字节发出后禁止失败重试。

- 生成协议覆盖图片、局部修改/扩图、图层拆分、视频、音频。参考素材按文件组上传，编辑过程图和图层元数据随产物回传。视频的上游订单只由网关持有，接入端重启后续查网关任务；提交未确认或已有订单时不重新提交。
- 限额改为日/周/月人民币金额窗口，按网关本地日历重置。受理时原子预占估价，终态释放预占并结算实际费用（无实际费用则成功按估价）；无价格调用计零并在用量中标出未计价。权限按模型路由和上游 alias 过滤，空数组表示无权限。
- 欠费按模态和 alias 持久化，一小时后允许试探，失败顺延；成功或本机管理页手动恢复后清除。全组欠费不强行重试。限流保留内存冷却，接入端遇到额度 429 按 Retry-After 冷却网关成员。
- 管理接口、用量和产物预览只在主服务，要求本机管理会话。实时事件复用主服务 SSE，只有 local 会话能收到生成任务 prompt，agent 会话不可接收；文本调用不提供 prompt。接入端本人额度由主服务代查并缓存 30 秒，失败静默隐藏。
- 两端要求协议 v2，不保留旧张数限额兼容路径。5.103.0 先交付 dev，Windows 真机联调完成后再由用户决定同步 main。
