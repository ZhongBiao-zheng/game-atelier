# Interaction 模板（UI 交互逻辑）

> 所有 `projects/<slug>/design/interaction.md` 遵循此格式。
> 三锚文档之一，正式门禁规则见 `gdd-template.md` 头部说明。
> 页面生图 prompt 必须能直接引用本文件的主流程与状态名——
> **状态名一经批准即是契约**，screen brief / prompt 里的状态用语必须与此处一致。
> 禁止占位词；没问清的字段整行省略。

---

## 格式规范

### YAML frontmatter（必填元数据）

```yaml
---
project: <project-slug>
status: draft | approved
updated: YYYY-MM-DD
---
```

### 全局交互原则

```markdown
## 全局交互原则
- <每条一行：热区 / 反馈层级 / 主次操作对比 / 破坏性操作确认等，只写本项目真的要执行的>
```

### 全局导航

```markdown
## 全局导航
| 入口 | 目标页 | 高亮规则 |
|---|---|---|
| <导航项> | <screen-id> | <何时高亮> |
```

### 全局状态（跨页面通用态）

```markdown
## 全局状态
| 状态 | 触发 | UI 表现 |
|---|---|---|
| loading | <触发条件> | <表现> |
```

### 分页面交互（每个 must-have 页面一节）

```markdown
## screen.<screen-id>（页面名）
- 目的: <一句话>
- 进入来源: <从哪来>
- 离开去向: <到哪去>

### 主流程
<一行箭头链：进入 → 看见什么 → 主操作 → 成功/失败分支 → 离开或停留>

### 控件与行为
| 控件 | 操作 | 成功结果 | 失败/空态 |
|---|---|---|---|
| <控件名> | tap | <结果> | <表现> |

### 状态机
| 状态 | 可见内容 | 切换条件 |
|---|---|---|
| default | <内容> | <条件> |

### 视觉稿约束
- 首屏必须露出: <信息列表>
- 生图需强调的主操作: <控件名>
```

（弹窗/二次确认场景写进「控件与行为」的失败列或单独加行，不另立节。）

### 跨页链路

```markdown
## 跨页链路
1. <页 A → 页 B → 页 C 的典型玩家路径，每条一行>
```

### 验收清单

```markdown
## 验收清单
- [ ] 每个 must-have 页面有主流程与至少一种失败/空态
- [ ] 导航高亮规则可执行
- [ ] 破坏性/付费操作有确认路径
- [ ] 状态名可被页面生图 prompt 直接引用
```
