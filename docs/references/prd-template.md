# PRD 模板（产品需求文档）

> 所有 `projects/<slug>/design/prd.md` 遵循此格式。
> 三锚文档之一，正式门禁规则见 `gdd-template.md` 头部说明。
> 铁律：**每条 P0 需求必须被某个页面承接**——「对应页面」列不得为空；
> 页面范围表是 screen-map（B4）与逐页生成的唯一上游。
> 禁止占位词；没问清的字段整行省略。

---

## 格式规范

### YAML frontmatter（必填元数据）

```yaml
---
project: <project-slug>
status: draft | approved
updated: YYYY-MM-DD
---
```

### 概述

```markdown
## 概述
- 产品目标: <一句话>
- 非目标: <明确不做的事，分号分隔>
```

### 需求（按优先级，每条必须落到页面）

```markdown
## 需求
### P0（必须）
| ID | 需求 | 对应页面 | 验收标准 |
|---|---|---|---|
| PRD-01 | <需求> | <screen-id> | <可验证的一句话> |

### P1（重要）
| ID | 需求 | 对应页面 | 验收标准 |
|---|---|---|---|
| PRD-11 | <需求> | <screen-id> | <可验证的一句话> |
```

（P2 可选，结构同上；没有就省略该节。）

### 信息架构

```markdown
## 信息架构
- 一级导航: <入口列表，逗号分隔>
- 二级入口: <从哪进到哪，每条一行>
- 弹层模态: <全屏/弹窗清单>
```

### 页面范围（本迭代要生成的页面）

```markdown
## 页面范围
| screen-id | 名称 | 覆盖需求 | 生图优先级 |
|---|---|---|---|
| <id，小写连字符> | <中文名> | <PRD-xx 列表> | must-have / genre-specific / optional |
```

### 边界与异常（UI 需要表现的态）

```markdown
## 边界与异常
- <场景>: <UI 表现，如「网络失败: 顶部横条提示 + 重试按钮」>
```

### 验收清单

```markdown
## 验收清单
- [ ] P0 需求均有对应页面
- [ ] 每个 must-have 页面有主操作与空态
- [ ] 与 gdd.md 核心循环环节一一对应
- [ ] 与 interaction.md 分页章节一致
```
