# 游戏 UI AI 工作流 实施计划（Phase 1 MVP）

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建"一句话需求 → 概念图"两节点 AI 设计工作流（需求结构化 → Lovart 概念图生成），让美术可基于概念图直接进入 PS 精修。

**Architecture:** 两个独立 Skill（`game-ui:structuring` / `game-ui:concepting`）以文件契约通信，Skill 之间不直接传值，读上一步目录、写自己目录，任何节点失败可断点续跑。编排器 Skill `game-ui:run` 串联两步并在每步后触发人工 Gate 确认。所有图像生成通过 `lovart-api` skill 调用，不直接调用 API。

**Tech Stack:** Claude Code Skill System（symlink 模式开发）, Lovart API via `lovart-api` skill (GPT Image 2)

### Task 1: 边开发边测试 — `setup.sh` Symlink 安装脚本

**核心思路（来自 gamemaker/setup）：** Skill 源码放在仓库 `skills/` 目录（版本控制），通过 symlink 注册到 `~/.claude/skills/`。修改 SKILL.md 文件后**无需重新安装**，改动即时生效，支持边写边测。

**Files:**
- Create: `setup.sh`

- [ ] **Step 1: 创建 setup.sh**

写入 `setup.sh`：

```bash
#!/usr/bin/env bash
# setup.sh: 将 skills/ 下的每个 Skill 目录 symlink 到 ~/.claude/skills/
# 用法：
#   ./setup.sh           全局安装（~/.claude/skills/）
#   ./setup.sh --local   本地安装（.claude/skills/ in 当前目录）

set -e

REPO_DIR="$(cd "$(dirname "$0")" && pwd)"
INSTALL_DIR="$HOME/.claude/skills"
LOCAL=0

for arg in "$@"; do
  [ "$arg" = "--local" ] && LOCAL=1
done

if [ "$LOCAL" -eq 1 ]; then
  INSTALL_DIR="$(pwd)/.claude/skills"
fi

mkdir -p "$INSTALL_DIR"

linked=()
for skill_dir in "$REPO_DIR"/skills/*/; do
  [ -f "$skill_dir/SKILL.md" ] || continue
  dir_name="$(basename "$skill_dir")"

  # 优先读取 SKILL.md frontmatter 中的 name: 字段
  skill_link_name=$(grep -m1 '^name:' "$skill_dir/SKILL.md" 2>/dev/null \
    | sed 's/^name:[[:space:]]*//' \
    | sed 's/:/--/g' \
    | tr -d '[:space:]')
  [ -z "$skill_link_name" ] && skill_link_name="$dir_name"

  target="$INSTALL_DIR/$skill_link_name"
  ln -snf "$skill_dir" "$target"
  linked+=("$skill_link_name")
done

echo "✅ game-ui skills linked to $INSTALL_DIR"
echo "   skills: ${linked[*]}"
echo "   编辑 skills/ 目录下的 SKILL.md 文件，改动即时生效。"
```

# 视觉规范：宝可梦电竞风

## 色彩系统

| 角色 | 色值 | 用途 |
|---|---|---|
| Primary（主背景） | #1A1A2E | 大面积深宇宙蓝背景 |
| Secondary（面板） | #16213E | 卡片/面板/侧边栏背景 |
| Accent（强调） | #E94560 | CTA 按钮、进度条、高亮框 |

| Text-Primary | #E2E2E2 | 主要文字 |
| Text-Secondary | #9A9AB0 | 说明文字、次级标签 |

## 字体

- 标题：思源黑体 Bold（fallback: PingFang SC Bold）
- 正文：思源黑体 Regular
- 数字/评分：Roboto Mono 或 DIN Condensed（等宽）

## 特效规则

- 卡片边框：1px 渐变描边，从 Primary 渐变到 Accent，45° 方向
- 发光效果：`box-shadow: 0 0 8px rgba(233, 69, 96, 0.6)`
- 背景纹理：极细六边形网格叠加，`opacity: 0.05`
- 过渡时长：200ms ease-out

## 图标风格

- 线框 + 填充混合（非纯线框，非纯填充）
- 统一圆角：2px
- 尺寸规格：16 / 24 / 32 / 48px 四档

## 禁止项

- ❌ 纯白底色（#FFFFFF）
- ❌ 超过 3 种强调色共存于同一视图
- ❌ 无发光效果的纯色大按钮
- ❌ 无描边的浮层面板

# Skill-1 需求结构化 Prompt 模板

## 系统角色

你是游戏 UI 需求分析师，将策划的口语化需求转化为 AI 可执行的结构化 JSON。
使用 `design-system/component-taxonomy.md` 中的枚举约束所有 component id。

## 输出 JSON Schema

```json
{
  "page": "string — 页面名称，如 赛后结算页",
  "sections": ["string — 视觉区域名称，如 英雄展示区、队伍数据区"],
  "components": [
    {
      "id": "string — {类别_key}_{描述}，来自 component-taxonomy",
      "label": "string — 中文说明",
      "section": "string — 所属区域",
      "required": true
    }
  ],
  "layout_description": "string — 布局描述，图像生成可直接使用。描述主要元素的位置关系，如 hero card centered top, score table below center, CTA button bottom center",
  "design_constraints": ["string — 设计约束，如 MVP 卡片必须最突出"],
  "hierarchy": "string — 视觉重心描述，如 MVP 卡片 > 积分榜 > CTA 按钮"
}
```

## 规则

- `id` 必须来自 component-taxonomy 7 类枚举的类别 key，不得自造
- 未在 taxonomy 中的组件，用最近似类别命名并在 `design_constraints` 中标注
- `layout_description` 用英文，会直接拼入图像生成 Prompt
