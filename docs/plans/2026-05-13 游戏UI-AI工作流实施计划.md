# 游戏 UI AI 工作流 实施计划（Phase 1 MVP）

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建"一句话需求 → 低保真线框 → 概念图"三节点 AI 设计工作流（需求结构化 → Pencil 线框生成 → Lovart 概念图生成），让美术可基于概念图直接进入 PS 精修。

**Architecture:** 三个独立 Skill（`game-ui:structuring` / `game-ui:wireframing` / `game-ui:concepting`）以文件契约通信，Skill 之间不直接传值，读上一步目录、写自己目录，任何节点失败可断点续跑。Pencil 只负责生成低保真线框原型，不负责 UI 拆分后的素材回填。编排器 Skill `game-ui:run` 作为复合执行说明，顺序执行三个节点并在每步后触发人工 Gate 确认。所有图像生成通过 `lovart-api` skill 调用，不直接调用 API；Lovart 出图必须附加线框截图和 UI 风格参考图。

**Tech Stack:** Claude Code Skill System（项目内 symlink 模式开发）, Pencil MCP (`mcp__pencil__*`), Lovart API via `lovart-api` skill (GPT Image 2)

**Skill 安装模型：**
- `skills/` 是唯一源码目录，纳入版本控制。

- `~/.claude/skills/` 是全局 registry，只同步指向本项目 `.claude/skills/` 的 symlink。
- 同步方向固定为：`skills/` → `.claude/skills/` → `~/.claude/skills/`。不要反向从全局目录改源码。

```bash
#!/usr/bin/env bash
# setup.sh: 将 skills/ 同步为项目本地 symlink registry，再同步到全局 registry
# 用法：
#   ./setup.sh           生成 .claude/skills/，并同步到 ~/.claude/skills/
#   ./setup.sh --local   只生成项目本地 .claude/skills/

set -euo pipefail

REPO_DIR="$(cd "$(dirname "$0")" && pwd)"
SOURCE_DIR="$REPO_DIR/skills"
LOCAL_REGISTRY="$REPO_DIR/.claude/skills"
GLOBAL_REGISTRY="$HOME/.claude/skills"
SYNC_GLOBAL=1

for arg in "$@"; do
  case "$arg" in
    --local) SYNC_GLOBAL=0 ;;
    --global) SYNC_GLOBAL=1 ;;
    *) echo "Unknown argument: $arg" >&2; exit 1 ;;
  esac
done

mkdir -p "$LOCAL_REGISTRY"
[ "$SYNC_GLOBAL" -eq 1 ] && mkdir -p "$GLOBAL_REGISTRY"

link_skill() {
  source_path="$1"
  target_path="$2"

  if { [ -e "$target_path" ] || [ -L "$target_path" ]; } && [ ! -L "$target_path" ]; then
    echo "Refusing to overwrite non-symlink: $target_path" >&2
    echo "Move or delete it manually, then rerun setup.sh." >&2
    exit 1
  fi

  ln -sfn "$source_path" "$target_path"
}

linked=()
for skill_dir in "$SOURCE_DIR"/*/; do
  [ -d "$skill_dir" ] || continue
  [ -f "$skill_dir/SKILL.md" ] || continue
  dir_name="$(basename "$skill_dir")"

  # 优先读取 SKILL.md frontmatter 中的 name: 字段
  skill_link_name=$(grep -m1 '^name:' "$skill_dir/SKILL.md" 2>/dev/null \
    | sed 's/^name:[[:space:]]*//' \
    | sed 's/:/-/g' \
    | tr -d '[:space:]')
  [ -z "$skill_link_name" ] && skill_link_name="$dir_name"

  local_target="$LOCAL_REGISTRY/$skill_link_name"
  link_skill "$skill_dir" "$local_target"

  if [ "$SYNC_GLOBAL" -eq 1 ]; then
    global_target="$GLOBAL_REGISTRY/$skill_link_name"
    link_skill "$local_target" "$global_target"
  fi

  linked+=("$skill_link_name")
done

if [ "${#linked[@]}" -eq 0 ]; then
  echo "No skills found in $SOURCE_DIR" >&2
  exit 1
fi

echo "✅ game-ui skills linked"
echo "   source:        $SOURCE_DIR"
echo "   project local: $LOCAL_REGISTRY"
if [ "$SYNC_GLOBAL" -eq 1 ]; then
  echo "   global:        $GLOBAL_REGISTRY"
else
  echo "   global:        skipped (--local)"
fi
echo "   skills: ${linked[*]}"
echo "   编辑 skills/ 目录下的 SKILL.md 文件，项目本地和全局入口都会即时生效。"
echo "   若本次首次创建 .claude/skills/，请重启 Claude Code 一次建立 watcher。"
```

# Skill-1 需求结构化 Prompt 模板

## 系统角色

你是游戏 UI 需求分析师，将策划的口语化需求转化为 AI 可执行的结构化 JSON。
使用 `design-system/component-taxonomy.md` 中的枚举约束所有 component id，使用 `design-system/slot-conventions.md` 约束线框插槽。

## 输出 JSON Schema

```json
{
  "page": "string — 页面名称，如 赛后结算页",
  "sections": ["string — 视觉区域名称，如 英雄展示区、队伍数据区"],
  "components": [
    {
      "id": "string — {类别_key}_{描述}，来自 component-taxonomy",
      "label": "string — 中文说明",
      "section": "string — 所属区域",
      "required": true
    }
  ],
  "slots": [
    {
      "slot_id": "string — slot_{类别_key}_{描述}",
      "component": "string — 对应 component id",
      "position": "string — top_center | center | bottom_right 等",
      "size": "string — WxH，参考 component-taxonomy 标准尺寸",
      "priority": "string — primary | secondary | tertiary"
    }
  ],
  "design_constraints": ["string — 设计约束，如 MVP 卡片必须最突出"],
  "hierarchy": "string — 视觉重心描述，如 MVP 卡片 > 积分榜 > CTA 按钮"
}
```

## 规则

- `id` 必须来自 component-taxonomy 7 类枚举的类别 key，不得自造
- 未在 taxonomy 中的组件，用最近似类别命名并在 `design_constraints` 中标注
- `slots` 数组与 `components` 一一对应，每个 required 组件必须有对应插槽
- `priority` 用于线框视觉层级和后续概念图 Prompt 生成，不用于自动绘制复杂样式
```

# Skill-2 线框生成 Prompt 模板

## Pencil MCP 工具调用顺序

```
mcp__pencil__open_document
  → mcp__pencil__find_empty_space_on_canvas（确定起点）
  → mcp__pencil__batch_design（批量创建所有占位块）
  → mcp__pencil__get_screenshot（截图）
  → mcp__pencil__export_nodes（导出 .pen / PNG 交付物）
```

## 每个 slot 的 batch_design 参数

- 形状：矩形或简单 frame，占位为主，不画高保真样式
- 填色：#E5E5E5（灰白）
- 描边：1px #CCCCCC
- 标注文字：`{slot_id}`，居中，14px，颜色 #666666
- 尺寸：取 slots JSON 中 `size` 字段（WxH）
- 位置：按 `position` 枚举值排布（top=顶部, center=垂直居中, bottom=底部）
- 层级：`priority=primary` 的插槽尺寸和位置优先保证

## 输出契约

- `*-线框-v{N}.png`：截图，用于 Gate 2 确认和 Skill-3 输入
- `*-线框-v{N}.pen`：Pencil 源文件
- `*-线框-v{N}.slots.json`：从 requirements JSON 的 slots 数组提取，加入 Pencil node_id
- `*-线框-v{N}.meta.json`：元数据（见 Skill 实现）
```
