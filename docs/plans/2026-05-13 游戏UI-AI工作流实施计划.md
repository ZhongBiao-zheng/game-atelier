# 游戏 UI AI 工作流 实施计划（Phase 1 MVP）

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建"一句话需求 → 概念图"三节点 AI 设计工作流，让美术可基于概念图直接进入 PS 精修。

**Architecture:** 三个独立 Skill（`game-ui:structuring` / `game-ui:wireframing` / `game-ui:concepting`）以文件契约通信，Skill 之间不直接传值，每个 Skill 读上一步目录、写自己目录，任何节点失败可断点续跑。编排器 Skill `game-ui:run` 串联三步并在每步后触发人工 Gate 确认。

**Tech Stack:** Claude Code Skill System, Pencil MCP (`mcp__pencil__*`), Lovart API via `lovart-api` skill (GPT Image 2)

# 视觉规范：宝可梦电竞风

## 色彩系统

| 角色 | 色值 | 用途 |
|---|---|---|
| Primary（主背景） | #1A1A2E | 大面积深宇宙蓝背景 |
| Secondary（面板） | #16213E | 卡片/面板/侧边栏背景 |
| Accent（强调） | #E94560 | CTA 按钮、进度条、高亮框 |
| Highlight（金色） | #F5A623 | MVP 徽章、高分标注、稀有物品 |
| Text-Primary | #E2E2E2 | 主要文字 |
| Text-Secondary | #9A9AB0 | 说明文字、次级标签 |

## 字体

- 标题：思源黑体 Bold（fallback: PingFang SC Bold）
- 正文：思源黑体 Regular
- 数字/评分：Roboto Mono 或 DIN Condensed（等宽）

## 特效规则

- 卡片边框：1px 渐变描边，从 Primary 渐变到 Accent，45° 方向
- 发光效果：`box-shadow: 0 0 8px rgba(233, 69, 96, 0.6)`
- 背景纹理：极细六边形网格叠加，`opacity: 0.05`
- 过渡时长：200ms ease-out

## 图标风格

- 线框 + 填充混合（非纯线框，非纯填充）
- 统一圆角：2px
- 尺寸规格：16 / 24 / 32 / 48px 四档

## 禁止项

- ❌ 纯白底色（#FFFFFF）
- ❌ 超过 3 种强调色共存于同一视图
- ❌ 无发光效果的纯色大按钮
- ❌ 无描边的浮层面板
```

# Pencil 插槽命名约定

## 格式

`slot_{类别_key}_{描述}`

|---|---|---|
| slot_card_hero | card_hero | 英雄卡片占位区 |
| slot_btn_primary | btn_primary | 主 CTA 按钮 |
| slot_panel_result | panel_result | 赛后结算主面板 |
| slot_icon_mvp | icon_mvp | MVP 图标 |
| slot_bg_main | bg_main | 主背景 |
| slot_text_score | text_score | 分数文字块 |

## Skill-1 输出 JSON 中 slots 的契约格式

`game-ui:structuring` 输出的 JSON 必须包含 `slots` 数组，每个元素：

  "slot_id": "slot_card_hero",
  "component": "card_hero",
  "position": "top_center",
  "size": "320x200"
}

`position` 枚举值：`top_left` / `top_center` / `top_right` / `center_left` / `center` / `center_right` / `bottom_left` / `bottom_center` / `bottom_right`

# Skill-1 需求结构化 Prompt 模板

## 系统角色

你是游戏 UI 需求分析师，将策划的口语化需求转化为 AI 可执行的结构化 JSON。
使用 `design-system/component-taxonomy.md` 中的枚举约束所有 component id 和 slot_id。

## 输出 JSON Schema

```json
{
  "page": "string — 页面名称，如 赛后结算页",
  "sections": ["string — 视觉区域名称，如 英雄展示区、队伍数据区"],
  "components": [
    {
      "id": "string — {类别_key}_{描述}，来自 component-taxonomy",
      "label": "string — 中文说明",
      "section": "string — 所属区域",
      "required": true
    }
  ],
  "slots": [
    {
      "slot_id": "string — slot_{类别_key}_{描述}",
      "component": "string — 对应 component id",
      "position": "string — top_center | center | bottom_right 等",
      "size": "string — WxH，参考 component-taxonomy 标准尺寸"
    }
  ],
  "design_constraints": ["string — 设计约束，如 MVP 卡片必须最突出"],
  "hierarchy": "string — 视觉重心描述，如 MVP 卡片 > 积分榜 > CTA 按钮"
}
```

## 规则

- `id` 必须来自 component-taxonomy 7 类枚举的类别 key，不得自造
- 未在 taxonomy 中的组件，用最近似类别命名并在 `design_constraints` 中标注
- `slots` 数组与 `components` 一一对应，每个 required 组件必须有对应插槽
```

# Skill-2 线框生成 Prompt 模板

## Pencil MCP 工具调用顺序

```
mcp__pencil__open_document
  → mcp__pencil__find_empty_space_on_canvas（确定起点）
  → mcp__pencil__batch_design（批量创建所有占位块）
  → mcp__pencil__get_screenshot（截图）
  → mcp__pencil__export_nodes（可选，导出 SVG）
```

## 每个 slot 的 batch_design 参数

- 形状：矩形
- 填色：#E5E5E5（灰白）
- 描边：1px #CCCCCC
- 标注文字：`{slot_id}`，居中，14px，颜色 #666666
- 尺寸：取 slots JSON 中 `size` 字段（WxH）
- 位置：按 `position` 枚举值排布（top=顶部, center=垂直居中, bottom=底部）

## 输出契约

- `*-线框-v{N}.png`：截图，用于 Gate 2 确认和 Skill-3 输入
- `*-线框-v{N}.slots.json`：从 requirements JSON 的 slots 数组提取，加入 Pencil node_id
- `*-线框-v{N}.meta.json`：元数据（见 Skill 实现）
```

# game-ui:wireframing

执行 Skill-2：从结构化 JSON 生成 Pencil 低保真线框。

**slots.json 格式：**

]

```json
{
  "model": "pencil-mcp",

# game-ui:run

一键串联完整设计工作流（Phase 1 MVP）。

## 使用方式

在 task 目录下直接运行，或在项目根目录指定路径：
```
/game-ui:run
/game-ui:run tasks/2026-05-12-赛后结算页
```

## 前置检查

1. 确定 task 目录（当前目录或参数指定）
2. 确认 `brief.md` 存在且非空
3. 确认 `design-system/visual-style.md` 存在（规范就绪）

## 流程

### A. 需求结构化

调用 `game-ui:structuring`，输出结构化 JSON 摘要。

**等待 Gate 1 确认：**
- 用户说"确认"/"OK"/"继续" → Step B
- 用户提出修改 → 按反馈修改 JSON，更新 meta.json 时间戳，继续 Step B
- 用户说"重来" → 删除 01-requirements/ 内容，重新运行 structuring

### B. 线框生成

调用 `game-ui:wireframing`，生成 Pencil 线框截图。

**等待 Gate 2 确认：**
- 用户说"确认"/"OK" → Step C
- 用户提出布局调整 → 修改 requirements JSON 中 slots 的 position/size，重新运行 wireframing（版本号递增）

### C. 概念图生成

调用 `game-ui:concepting`，生成风格概念图。

**等待 Gate 3 确认：**
- 用户说"确认"/"OK" → 输出交付摘要，结束
- 用户提出风格调整 → 收集反馈，修改 Prompt（升版），重新运行 concepting
