## 一、这是什么

嵌在画师日常工作流里的**角色出图协作工具**。

核心三件套：
1. **角色档案**——一份 Markdown 文档，把一个角色"画成什么样"沉淀成可复用的结构化信息。
2. **AI 出图**——AI 根据角色档案自动生成提示词，调 GPT Image 2 出图。
3. **聊天迭代**——画师对图不满意时，在聊天里直接说"哪里要改"，AI 改提示词、和画师确认后重出图，并把修改意见沉淀进项目长期记忆。

画师**不离开聊天窗口**，就能把一个角色从"档案"推到"可用立绘"。

---

## 二、能做什么（V1 范围）

每条都对应画师真实工作中的一个动作。

### 2.1 建角色档案【V1】

- 画师在聊天里描述一个新角色（可以一两句话开头，也可以一次性塞一大段）。
- AI 把零散描述整理成结构化的**角色档案 Markdown 文件**，存到项目内 `characters/{character_id}.md`。
- **档案生成后，AI 把档案原文在聊天里贴出来给画师看**——画师可以直接说"这里改一下"，AI 修订后再贴。
- 反复迭代直到画师确认。

### 2.2 修角色档案【V1】

- 画师在聊天里说"把暗影战士的发色换成银色 / 把武器从矛改成双刃刀"。
- AI 改对应字段，把改动后的档案再贴一次给画师确认。
- 旧版档案由 Git 自动保留版本，可回滚。

### 2.3 单张角色立绘出图（核心流程）【V1】

按时间顺序：

1. 画师说"给暗影战士出一张立绘"。
2. AI 读档案，生成完整提示词。
3. **AI 在聊天里把提示词原文贴出来给画师过目**（不直接出图）。
4. 画师有意见 → 直接说"把武器描述改成更朴素" → AI 改完再贴 → 画师确认。
5. 画师确认后 → AI 调 GPT Image 2 出图。
6. 出图下载到画师本地图片目录，按命名规则命名（见 §4.3）。
7. 出图在聊天里通知画师，B 阶段起可在浏览器看图面板查看（见 §六）。

### 2.4 聊天式迭代（出图后改提示词）【V1】

- 出图后画师说"头发太花了 / 武器位置不对 / 整体偏黑了"。
- AI 把反馈翻译成提示词修订。
- AI 先贴改后的提示词给画师过目 → 确认 → 再出图。
- **每一轮都走"提示词预览 → 画师确认 → 出图"的环，程序不会跳过这个确认步骤。**

### 2.5 修改意见沉淀到项目长期记忆【V1】

- 每一次有效的修改意见（"这个角色头发不要画太花"），被 AI 提炼成一句规律，写入 `memory/character-prefs.md`。
- 下次给同一角色出图，AI 自动套用这些规律，画师不用重复同一条意见。
- 项目通用规律（"本项目所有女性角色不要露脐"）也沉淀进同一文件。
- 画师可随时在聊天里说"忘掉之前关于发型的那条规则"来清理记忆。

### 2.6 同一角色再次出图（复用）【V1】

- 画师说"再给暗影战士出一张换个姿势的立绘"。
- AI 直接套用沉淀的修改意见 + 既有档案，画师不用从头交代上次的所有意见。
- 仍然走"提示词预览 → 画师确认 → 出图"的环。

### 2.7 参考图按需注入（支持多张）【V1】

- 画师可在角色档案里**手填 0 张到 N 张参考图路径**——一张都不给也行，给五张也行。
- 参考图按需注入到 GPT Image 2 的输入里，在提示词预览时一并告知画师引用了哪些。
- 画师也可在聊天里临时说"这次出图参考一下 design-system/references/xxx.webp"，单次有效，不写进档案。

### 2.8 模型备用切换【V1】

- 默认走 GPT Image 2。
- 画师可在聊天里说"这次换 nano banana pro 试试"——临时切换，单次有效。
- GPT Image 2 出现故障 / 配额耗尽时，AI 自动告知并询问是否切备用模型。

## 三、暂时不做（V2 路线）

V1 上线后跑稳，再启动 V2。下面这些**明确不在 V1 承诺里**：

- 角色三视图（正 / 侧 / 背）的批量出图
- 角色美宣海报
- 角色分镜 / Q 版头像 / 表情包
- 跨多张图的视觉一致性**自动保证**（V1 由画师人工把关，AI 不主动检查）
- 风格漂移自动检测与告警（不做——画师对风格的眼力比 AI 强）
- 跨项目的角色档案库检索与复用

## 四、输入输出契约

### 4.1 角色档案文件

- **格式**：Markdown 纯文本（不是 JSON）
- **储存位置**：项目内 `characters/{character_id}.md`
- **命名**：`character_id` 用 snake_case 英文，如 `shadow_spear_warrior.md`
- 画师可以自由删字段、加字段——这是**给人读的文档**，不是给程序解析的协议

**字段模板**（待美术负责人确认增删，见 §八问题 1）：

```markdown
# 暗影之矛战士 / Shadow Spear Warrior

## 基本信息
- ID: shadow_spear_warrior
- 角色定位: 近战刺客
- 世界观: 暗黑奇幻 / 影族流亡者

## 外观
- 性别: 女
- 年龄段: 青年（24岁）
- 体型: 修长精瘦，长期战斗训练
- 肤色: 苍白冷调，左颧骨有一道淡疤（童年逃亡时的箭伤）
- 发型: 黑色长辫至腰，辫尾缀三颗银珠（代表已完成的三次刺杀）
- 眼睛: 紫色虹膜，微弱发光——影族血脉觉醒标志
- 服装: 深色皮甲 + 影丝兜帽，腰侧挂赫卡-那神纹小皮囊
- 标志武器: 黑曜石长矛"夜噬"，矛身刻紫色符文，可吸取怨念

## 风格基线
- 美术风格: 半写实风格化（参考《暗黑破坏神 4》刺客质感）
- 色调: 冷暗主调（炭黑/深紫为主），紫色点缀光效，绝不出现暖色高光
- 氛围: 潜行、肃杀、克制压抑
- 头身比: 7.5-8

## 参考图（0～N 张，按需填）
- design-system/references/shadow_aesthetic_01.png（整体氛围基线）
- design-system/references/leather_armor_dark_02.png（皮甲细节）
- design-system/references/obsidian_weapon_01.png（武器质感）

## 反向约束（不要出现的元素）
- 不要明亮欢快色调
- 不要露脐 / 性感化服装裁剪
- 不要卡通比例
- 不要面带笑容
- 不要持矛之外的武器同框
- 不要暖色高光

## 备注
（画师补充的任何信息）
```

### 4.2 提示词

- **语言**：中文优先。GPT Image 2 / Nano Banana Pro 对中文支持已经很好，画师能直接读懂、直接改，沟通成本更低。画师指定时可切英文。
- AI 在聊天里发**正向提示词 + 反向提示词**两段纯文本，画师可直接说"把武器那句换成 X"，AI 改完再贴。
- **硬规则：画师在没确认 prompt 前，程序不出图。**

提示词展示示例：

> 准备出图，请确认提示词：
>
> **正向**：青年女性，24岁，纤瘦精瘦体型，苍白冷调肌肤，左颧骨淡疤，黑色长辫缀三颗银珠，紫色微光眼瞳，神情冷静不带笑意，深色皮甲配影丝兜帽，手持黑曜石长矛矛身刻紫色符文，炭黑深紫主调点缀紫色光效，半写实风格化，7.5头身比
>
> **反向**：明亮欢快色调，露脐，性感化服装，卡通比例，面带笑容，暖色高光
>
> **参考图**：shadow_aesthetic_01.png（氛围基线）、leather_armor_dark_02.png（皮甲细节）
>
> 确认出图？还是要改 prompt？

### 4.3 出图文件

- **储存位置**：画师本地配置的图片目录（不进 Git），按角色分子目录
- **初次配置**：打开 Web 看图面板时，设置页让画师选 / 粘贴图片目录路径（见 §六）

**命名规范**（待美术负责人确认，见 §八问题 2）：

```
<image_storage_root>/<character_id>/<场景短语>_<时间戳>_<序号>.png

示例：
.../shadow_spear_warrior/standing_20260515-1430_01.png
.../shadow_spear_warrior/standing_20260515-1430_02.png
.../shadow_spear_warrior/attack_20260516-0930_01.png
```

### 4.4 项目长期记忆文件

- **储存位置**：项目内 `memory/character-prefs.md`（进 Git，画师可读可改）
- **维护方式**：AI 自动追加 + 画师在聊天里直接命令增删

```markdown
## 项目级规律（所有角色通用）
- 本项目所有女性角色不露脐
- 武器一律朴素，不要繁复雕花

## 角色级规律

### shadow_spear_warrior
- 头发不要画太花（2026-05-15，第2轮出图反馈）
- 皮甲色调要接近炭黑，不要中灰（2026-05-16，第3轮出图反馈）
```

## 五、典型工作流（完整走一遍）

### 场景 A：新角色，第一张图

1. 画师 → "我要做一个暗影族女战士，长发黑色，紫眼，用黑曜石长矛，整体冷暗调。"
2. AI 整理成角色档案 → 贴给画师看 → 画师改两处 → 确认。
3. 画师 → "出张正面立绘。"
4. AI 读档案、生成提示词 → 贴提示词给画师看 → 画师说"加一句动感姿势" → AI 改完再贴 → 画师确认 → 出图。
5. 文件存到 `<image_storage_root>/shadow_spear_warrior/standing_20260515-1430_01.png`。
6. 画师审图，发现"头发太花、武器太短"。
7. 画师 → "头发不要那么花，武器矛身延长一倍。" → AI 改提示词 → 贴给画师看 → 画师确认 → 出图（_02）。
8. 同时，"暗影战士头发不要画太花"被 AI 写进 `memory/character-prefs.md`。
9. 画师满意 → 进入 PS 优化（不在本工具范围）。

### 场景 B：已有角色，新场景

1. 画师 → "再给暗影战士出一张侧面立绘。"
2. AI 自动套档案 + 之前沉淀的偏好 → 提示词预览 → 画师确认 → 出图。
3. 画师不用重复"头发不要花"这类已经沉淀的意见。

## 六、产品形态（简版结论）

**V1（B 阶段）= Claude Code 终端对话 + 本地 Web 只读看图面板**

- 画师在终端聊天窗口对话、确认 prompt、给反馈（主交互）
- 出图完成后可打开浏览器图廊，看图、对比（观察窗，不可写）
- 全程本地运行，无服务器、无云账号

**V2（C 阶段）= Web UI 升为主交互**（B 上线验证后再启动，不提前锁定）

- 画师在浏览器里聊天、看图、改档案，终端只需输"继续"
- 架构不变，文件系统仍是唯一数据源

技术架构、文件模型、B/C 阶段完整设计见 [产品形态设计方案](./2026-05-14%20游戏角色资产工作流-产品形态设计方案.md)。

## 八、待美术负责人确认的开放问题

请逐条给意见：

1. **角色档案字段**：§4.1 的模板字段，是否覆盖了做一个角色立绘所需的关键信息？还缺什么字段？哪些字段画师其实不会填、可以删？
2. **出图命名**：§4.3 的 `<场景短语>_<时间戳>_<序号>.png` 草案能用吗？要不要加任务号或项目代号？
3. **命名语言**：现有参考图是中文命名（`UI风格参考-角色面板.webp`），出图统一用英文 snake_case（草案），还是也走中文命名？
4. **参考图习惯**：画师通常一次给几张参考图？影响档案模板的默认字段数量。
5. **记忆透明度**：AI 自动沉淀修改意见到 `character-prefs.md`（顺滑），还是每次写之前都问一句"要不要存"（可控）？
6. **档案确认环节**：建档后是否一定要画师确认才能出图？还是允许"档案出来就直接出图，不满意再改"？前者更稳，后者更快。
7. **产品形态接受度**：让画师在终端聊天窗口里使用这个工具，你判断接受度大致如何？（影响 V2 是否需要做完整 Web 主交互）

## 九、不在 V1 承诺里的事（防误解）

- AI 不会自动判断风格漂移、不会跨图比对一致性——靠**画师人眼把关 + 档案复用 + 长期记忆沉淀**。
- AI 不会绕过角色档案直接出图——所有出图都必须有对应的角色档案。
- AI 不会强制画师走完整流程——这是工具，不是枷锁。画师随时可以绕过 AI 手动改文件。

## 十、风险

| 风险 | 说明 |
|---|---|
| **画师配合度** | 需要在新流程上花一些上手时间。计划用 30-60 分钟 demo + 上手指南覆盖。 |
| **跨场景视觉一致性** | V1 只承诺"风格大致接近"，强一致性是 V2 目标。 |
| **模型供应** | 备用模型清单已纳入，主模型停服时可平滑切换。 |
| **Lovart 配额成本** | 上线前确认预算与配额上限，V1 默认单次出图量上限 4 张。 |
| **IP / 版权** | 商用立绘的版权合规由老板/法务确认，与工具无关。 |
