## 框架设计原则

三条贯穿整个工作流的约束，结构和工具都围绕这三条展开：

1. **文件契约通信**：Skill 之间不直接传值，而是读上一步目录、写自己的目录。任何节点失败可断点续跑、可手工介入修改产物再继续。
2. **版本可追溯**：每次 Skill 出图都写一对 `{产物}` + `{产物}.meta.json`，meta 用 `prompt_version` 字段引用 `prompts/` 下的 Prompt 版本。从任意一张图都能反查到 Prompt、模型参数、视觉规范版本和时间戳。**Prompt 自身有版本号，与图版本解耦** —— 一次 Prompt 修改通常需要重摇多次才能验证效果，不该被图版本绑架。
3. **决策落盘**:每个 task 一份 `decisions.md`,记录每个 Gate 的判断、迭代原因、最终选哪一版。AI 不靠记忆,人也不靠脑子。

视觉规范、组件分类、Prompt 模板等跨任务复用的内容,放 `design-system/` 并带 `version:` frontmatter,被引用方在 `meta.json` 里记录用的版本号。

## 项目结构

术语区分：
- **工作流项目**：本仓库 `game-ui-ai-workflow/`，整套 AI 工作流的代码 + 规范 + 资产沉淀
- **设计任务 (task)**：一次具体的 UI 设计单元，例如「赛后结算页」「英雄选择界面」，每个 task 在 `tasks/` 下一个独立目录

### 命名规范

**1. 任务目录**

`tasks/{YYYY-MM-DD}-{任务名}/`，例：`tasks/2026-05-12-赛后结算页/`

**2. 产物文件**（会脱离 bundle 流通，必须自描述）

```
{YYYY-MM-DD}-{任务名}-{用途}-v{N}.{ext}
```

- `用途` 用纯中文，统一枚举：`需求 / 线框 / 概念图`（二阶段扩展 `组件 / 中保真`）
- `v{N}` 是该 Skill 输出的版本号，每次出图递增
- `.ext` 按产物类型：

| 产物 | 扩展名 |
|---|---|
| 图（线框截图 / 概念图） | `.png` |
| Pencil 源文件 | `.pen` |
| 需求 JSON | `.json` |
| 插槽映射 | `.slots.json` |

> 美术 PS 工程（`.psd` 等）不在 Skill 产物规范内 —— 命名由美术自管,但建议沿用同版本概念图的 stem,便于在 03-concepts/ 下 `ls *-v3.*` 一次看齐所有相关文件。

**3. 元数据文件**

`{产物 stem}.meta.json` —— 和产物同 stem，双扩展名 `.meta.json` 避免与产物 JSON 混淆。

最低字段：

```json
{
  "model": "gpt-image-2",
  "params": { "size": "1024x1024", "quality": "high" },
  "prompt_version": "03-概念图-v2",
  "style_version": "v0.1",
  "seed": 12345,
  "timestamp": "2026-05-12T15:32:00+08:00"
}
```

**4. Prompt 文件**（任务内 Prompt 版本史）

`prompts/{step}-{用途}-v{N}.md`，例：`prompts/03-概念图-v2.md`

**Prompt 升版规则**：Prompt 文本实质变化才升版（改风格、加约束、改结构）。只换 seed 重摇 **不升 Prompt 版本**，只在新 `meta.json` 里递增图版本号、复用旧的 `prompt_version`。

**5. 选中标记**

`SELECTED.txt`，内容一行，例：`v3`。跨平台无坑，不用符号链接。

### 一致性约束

- 同一版本的所有相关文件共享 stem，`ls *-v2.*` 可拿到该版本所有附属（图、meta、psd 等）
- 每个版本独立 append 两个文件（产物 + `.meta.json`），不修改任何老文件 —— 符合「文件契约通信」append-only 原则
- 跨任务复盘：`diff tasks/*/prompts/03-概念图-v*.md` 直接看 Prompt 演化
