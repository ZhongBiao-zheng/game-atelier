# 安全与隔离

插件界面运行在隔离的沙箱里（ADR-0012），服务端模块只允许随应用发布的插件带（ADR-0037）。这一页如实写明当前的隔离能保证什么、不能保证什么。所有结论在 Chrome 157（2026-11）实测，浏览器行为变化后需要重测。

## 沙箱怎么搭

- 插件界面是一个单文件 HTML。宿主以本机会话取回，按清单核对字节数与 SHA-256，不一致拒绝加载。
- 沙箱页面 = 宿主的固定前缀 + 包内容。前缀依次是内容安全策略和一段前缀脚本，永远排在最前面，宿主不在包内容里找插入位置。
- iframe 只开 `allow-scripts`：没有同源、表单、弹窗、顶层跳转、下载。沙箱是 opaque origin，读不到宿主页面、cookie 与本地存储，发出的请求不带本机会话。
- 内容安全策略不含任何网络来源：`default-src 'none'`、`connect-src 'none'`、`font-src 'none'`、`frame-src 'none'`、`form-action 'none'`、`base-uri 'none'`，脚本与样式只能是内联的。
- 宿主页面的响应头带 `frame-src 'none'`：没有指令能阻止沙箱帧把自己导航走，只有父页面能拦住那次加载。
- 握手证明：前缀脚本放下本次实例的 nonce，插件要在消息通道上先带回它，宿主在此之前不服务任何方法。握手发出时页面若已不是宿主拼的那份，对方拿到通道也用不了。

## 保证的

插件界面：

- 读不到宿主页面、其他插件的页面、cookie、本地存储、密钥。
- 指不到别的节点、别的项目、别的插件的数据：消息协议里没有节点、项目、路径参数；素材只能用本实例发出的句柄，且只限此刻连在本节点上的那些。
- 发不出这些请求：`fetch`（含 `no-cors`）、XHR、WebSocket、EventSource、`sendBeacon`、外部图片、脚本、样式、字体、动态 `import`、表单提交、嵌套子框架、弹窗、顶层跳转、把自己导航到别的地址（包括解析期间导航和返回 204 的连续导航）。
- 写入节点的数据只能是纯 JSON，大小、深度、条目数、字符合规都在写入前检查。

服务端：

- 插件路由要逐条声明；未启用的插件、未声明的路由在鉴权层就被拒绝，插件代码不会被触达。
- 每次调用都在服务端重新核对启用、声明、项目批准、节点归属与素材归属，不依赖浏览器侧。

## 不保证的（已知残余）

- **`<link rel="prerender">`**：浏览器会对目标地址发起一次 GET，地址里可以带数据。静态写在包里或用 `innerHTML` 插入的都会生效；宿主页面的 `frame-src`、沙箱内的 `default-src 'none'`、`prefetch-src`、`navigate-to` 都拦不住。
- **WebRTC**：`RTCPeerConnection` 能向任意地址发 STUN 包，内容安全策略管不到。前缀脚本把相关构造器置为不可用，实测直接使用和经 `about:blank` 子框架取回构造器都失败，但这是纵深防御，不构成边界。
- **`<script type="speculationrules">`**：prerender 与 prefetch 两种规则在沙箱帧里都没有发出请求；不带任何策略的对照组同样不发，所以这是浏览器不为这类帧执行推测规则，不是策略拦下的。浏览器行为变化后需要重测。

也就是说：插件读得到的数据（它自己的节点数据、用户连给它的素材）在上面两条残余通道上可以被带出。对插件的信任最终靠代码审核与发布者签名。

## 项目批准

- 用户在某个项目里第一次使用某插件时确认一次：一句话说明插件会做什么，「?」里写明它能读到连给它的素材完整内容（包括已隐藏的节点）。
- 批准绑定「项目 + 插件 + 包摘要」，不跨项目。插件更新后：随应用发布、能力没有增加的沿用原批准；能力增加了要重新批准。
- **撤销批准的生效时机**：服务端调用立即按新的状态拒绝；已经打开的插件界面要到重新挂载（刷新页面、重新打开画布）才失效，期间它仍能读写自己的节点数据、读连给它的素材。
- 批准记录不进项目包，换一台机器要重新批准。

## 服务端模块的信任

服务端模块与主程序同进程运行，能做主程序能做的一切，所以只允许随安装包发布、经代码审核的官方插件带。入库检查禁止它直接调用厂商接口与 Job Runner。

## 开放其他发布者之前必须完成

1. 包签名与发布者校验。
2. 两条残余的处置：在桌面外壳层关闭预加载与 WebRTC；或把界面包改为只含脚本与样式、外壳由宿主生成，并用 Trusted Types 与前缀脚本关掉已知写法（仍是脚本层防御，会限制插件能用的库）。
3. 宿主页面完整的基线内容安全策略（目前只有 `frame-src 'none'`）。
4. 服务端对节点数据深度与条目数的约束，用不在读盘时执行的方式实现（目前服务端只约束大小）。
5. 尚未实现的能力（读写画布结构、发起生成）与数据迁移。
