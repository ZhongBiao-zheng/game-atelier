# 版本兼容

| 版本 | 写在 | 不满足时 |
|---|---|---|
| `app_version.min` / `max` | 清单 | 设置页显示「需要 Atelier x.y.z 以上」或「仅支持到 Atelier x.y.z」，不能启用 |
| `sdk_version` | 清单 | 显示「需要更高版本的 Atelier」 |
| 能力 | 清单 `capabilities` | 有宿主不认识的能力时同上 |
| 必需的大文件 | 清单 `assets` | 下载器尚未实现，同上 |
| `payload_schema_version` | 节点类型 → 节点数据的 `data_schema_version` | 由插件界面自己兼容读取 |
| 包摘要 | 锁文件 `digest` | 见下方「升级插件」 |

官方插件随主程序一起发布、一起测试，正常情况下前四项都满足；这些规则为将来独立分发保留。

## 升级插件

- 改了界面、服务端模块或清单，包摘要就会变。
- 项目批准绑定包摘要：随应用发布的包、且新版本的能力不多于已批准的，沿用原批准并更新记录；能力增加了，用户要在每个项目里重新批准一次。
- 已打开的界面在插件更新后要重新挂载（刷新页面或重新打开画布）才会用上新版本。
- 节点数据格式变了：递增 `payload_schema_version`，新版本界面要能读旧格式；旧版本界面读到新格式时回落到默认值且不覆盖原数据。

## 宿主侧的承诺

- 协议主版本 `atelier-plugin/1` 内只增加方法与事件，不改已有方法的含义。
- 读画布不依赖插件，插件的增删、启停、升级都不会让画布打不开。
