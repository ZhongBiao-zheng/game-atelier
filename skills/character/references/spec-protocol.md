# Spec 填充协议 —— 对话驱动，禁止占位文档

## 核心规则

**永远不要生成"待补充"、"主色调?"、"留空"、"TBD"、"待定" 这类占位符。**

Why：画师反馈过 —— 看到一份满是 `?` 的文档，他需要回头改、统一回复、再粘贴。这把决策成本反推给画师，违背 Skill 的存在意义。Skill 的工作是**问对的问题**，把回答整理成档案，不是出一份让画师补全的表单。

## 怎么问

每个新角色档案至少要问清这 4 个维度才动笔写出图 prompt：

| # | 维度 | 高优先级问题示例 |
|---|------|---------------------|
| 1 | 风格档 | 写实 / 半写实 / 卡通 / Q版 / 像素？ |
| 2 | 配色与服装基调 | 主色调？是金白系神圣感，还是冷银系神秘感，还是暗黑系？ |
| 3 | 镜头与构图 | 全身 / 半身 / 三视图？站姿还是动作姿态？ |
| 4 | 关键道具与气质标志 | 一句话刻画她最有辨识度的视觉锚点（武器、表情、光效、姿态）？ |

### 提问节奏

- **一次问 1–3 个**。多了画师答不动，少了拖太久。
- **二选一或四选一优先于开放式**。"金白 vs 银蓝？" 比 "想要什么配色？" 好答。
- Claude Code 用 `AskUserQuestion` 工具时给具体选项，"Other" 由工具自动添加。
- Codex 用 `request_user_input` 时每题只给 2-3 个显式选项；需要 4 个业务选项时拆成两级选择。若当前模式没有该工具，则用编号列表等待用户回复，不继续行动。
- 画师明确放话"你定" → 直接定，写到档案的"已确定要点"里，并解释为什么这样定。

## 怎么写档案

每次画师答完一轮，把回答**即时归档**到当前角色 `character_spec`：先用
`workshop_read_document` 读取完整文档与 revision，再用 `workshop_write_document`
保存已确认内容及 expected_revision。文件仍属 `characters/<id>/spec.md`，但 Agent 不直写路径。

### 档案模板（无占位、按需扩展）

```markdown
# <角色显示名>

> id: `<id>`
> 创建时间：YYYY-MM-DD
> 最后更新：YYYY-MM-DD HH:MM

## 角色定位
- **职业**：祭祀
- **性别**：女
- **气质**：神圣、庄严

## 已确定要点
- 风格：半写实
- 主色调：金 + 白
- 镜头：全身正面，站姿
- 视觉锚点：右手持光辉法杖，左手抚胸前圣徽

## 出图 Prompt（中文）
（按 references/prompt-zh.md 生成；只在所有已确定要点齐了之后写）

## 出图记录
- 2026-05-18 14:30 · job-01ABC · 已生成 4 张 · 画师反馈"光感不够"
```

**没问清的维度，档案里就根本不出现这一节。** 等问清了再追加。

## 反例（不要这样做）

```markdown
## 视觉关键词（待画师补充）
- 服装：圣袍 / 法袍，主色调？
- 头饰：头冠 / 面纱？
- 道具：法杖 / 圣物 / 圣典？
- 配色：金 + 白 / 银 + 浅蓝 / 待定
```

这就是把决策成本扔回画师。**删掉，改用对话。**
