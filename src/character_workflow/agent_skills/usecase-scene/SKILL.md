# 场景概念与游戏背景

来源等级的含义见 prompt-method。项目规范里有世界观和配色的，以规范为准。

## 先分清用途
两种用途的默认画幅、必写项和骨架不同，分别写在下面两节。

- **概念图**：给人看气氛和世界观，可以有镜头感和事件。
- **游戏内背景**：要被程序使用，视角、分层、留空区域比气氛重要。

用户没说时，看上下文：提到「背景图」「关卡」「界面底图」按游戏内背景；提到「概念」「氛围」「世界观」按概念图。

## 概念图
- 画幅 16:9 或 2.39:1。
- 必写：世界观标签与时代；尺度参照物（前景的小人物、载具、建筑）；建立镜头的视角；材质与磨损；大气效果（体积光、云层、尘埃）；渲染路线（手绘概念稿、写实 CGI）。
- 写一个正在发生的事件（舰队入港、封印破裂），否则会变成静态风景。
- 色彩控制在有限组合，例如冷钢蓝加一种暖色点缀。
- 骨架：
```
[用途：游戏场景概念图，画幅] + [世界观与时代] + [地点与正在发生的事件] + [尺度参照] + [视角与镜头] + [主光源与大气] + [材质与磨损] + [色板] + [渲染路线]
```

## 游戏内背景
- 画幅跟游戏画面：横屏 16:9，竖屏 9:16，用户给了尺寸就用用户的。
- 必写：[通用]
  1. 游戏视角：横版侧视、俯视 45 度、正俯视、第一人称，四选一写死。
  2. 分层：前景、中景、远景各有什么；可行走的地面线在哪。
  3. 留空：角色和界面要占的区域保持简洁低对比（例如「画面下方三分之一是平整地面，不放高对比物体」）。
  4. 画面里没有角色、没有文字、没有界面元素。
  5. 光源方向单一，与同一关卡的其他素材一致。
- 需要可横向拼接的背景时，写「左右边缘可无缝衔接」，并在汇报里说明要人工检查接缝。
- 骨架：
```
[用途：游戏内背景，视角，画幅] + [地点与时段] + [前景 / 中景 / 远景] + [地面线与留空区域] + [光源方向] + [画风与色板] + [约束：无角色、无文字、无界面]
```

## 同一场景的多张图
白天、夜晚、雨天是三张不同的图，分别生成；用第一张作参考图，写「同一空间、同一机位，只改时段和光线」。

## 出图后看什么
- 视角是否符合要求。
- 留空区域是否足够干净。
- 有没有混进角色、文字或界面元素。
- 尺度参照是否成立（概念图）。
