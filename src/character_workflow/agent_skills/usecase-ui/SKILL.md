# 游戏界面

来源等级的含义见 prompt-method。本节多为通行做法，未在本产品实测。项目规范和类别规范优先；有同类参考图时先搜参考库。

## 先分清要哪一种
两种的默认画幅、必写项和骨架不同，分别写在下面两节。

- **整屏效果图**：看整体风格和布局，不直接切图使用。
- **界面素材**：单个按钮、面板、边框、底图，要能切图使用。

## 整屏效果图
- 画幅：手机横屏 16:9，竖屏 9:16；用户给了分辨率就用用户的，第一句写明。
- 必写：[通用]
  1. 界面类型（主界面、背包、商店、战斗界面、结算、弹窗）。
  2. 布局坐标化：顶部栏放什么，左侧、右侧、底部各放什么，主内容区占多大。
  3. 核心功能不超过 3 项。
  4. 界面文字用用户给的原文，加引号；没有给的写「文字区域用占位色块，不生成文字」。
  5. 风格与材质：扁平、拟物、木与金属、羊皮纸、玻璃质感。
  6. 主色与强调色。
- 把它当作已经上线的游戏来描述，不写「概念设计」「设计稿」。
- 正面平视，不要倾斜的手机样机，不要透视。
- 骨架：
```
[用途：手机游戏界面，类型，画幅] + [分区布局] + [各区内容] + [文字原文] + [风格与材质] + [配色] + [约束：正面平视、无样机、无多余文字]
```

## 界面素材
- 一张图一个素材，或一张图里排一套同风格的素材（写数量和排布）。
- 必写：[通用]
  1. 素材是什么（主按钮、关闭按钮、标题栏、物品格、对话框底板）。
  2. 形状与比例（圆角矩形，宽高约 3:1）。
  3. 材质与厚度（两层描边，内侧高光，底部投影）。
  4. 背景：纯色，或用透明背景参数。素材四周留边，不被裁切。
  5. 不带文字（文字由程序叠加），除非用户要。
- 按钮的不同状态（常态、按下、禁用）分别生成，或排在同一张图里并写清顺序。
- 可拉伸的面板和边框要写「四角装饰，四边纹理均匀可平铺」。

## 弹窗
弹窗通常需要底板、标题栏、按钮、关闭键几样东西。整屏效果图里一起画；要素材时分开出，并用第一张作画风参考。

## 限制
- 模型生成的界面文字、小图标和数值不可靠，在汇报里提醒用户核对。
- 精确的像素尺寸和切图边距，模型做不到，需要人工调整。

## 出图后看什么
- 布局是否符合分区描述。
- 文字是否是用户原文，有没有多出来的字。
- 素材是否正面、完整、背景干净。
